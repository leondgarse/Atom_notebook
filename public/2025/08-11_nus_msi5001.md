# WEEK 2 WHAT IS AI, LANDMARK AI ACHIEVEMENTS & SUBFIELDS OF AI
## What Is Artificial Intelligence (AI)?
  Based on:  
  - `W2P1 - What is AI?.txt` :contentReference[oaicite:0]{index=0}  

  AI is the study of **intelligent agents** that can perceive their environment, analyze information, learn from data, and take actions to achieve goals.

  Human intelligence follows:
  **Perceive → Think/Reason/Learn → Act**  
  AI mirrors this same loop using sensors, models, and algorithms.

  Examples from the lecture:
  - **Humanoid robot** uses cameras, microphones, GPS → learns and acts.  
  - **Siri/Voice assistants** interpret speech, run NLP models, perform tasks.  
  - **Google Maps** computes shortest path using GPS & algorithms.  
  - **Spam filtering** classifies emails based on content patterns.  
  - **Autonomous cars** use cameras, LIDAR, radar to drive safely.  
  - **Social media platforms** recommend posts using user behavior data.

  Two main categories:
  - **Artificial Narrow Intelligence (ANI)** → today’s AI, highly specialized  
  - **Artificial General Intelligence (AGI)** → theoretical, human-like reasoning across domains  

  AI is a field built on computational algorithms aiming to reproduce human-like intelligent behavior.

# WEEK 3 MACHINE LEARNING BASICS, DATA TYPES & KNN
## What is Machine Learning?
  Based on:  
  - `W3P1 - What is Machine Learning?.txt` :contentReference[oaicite:0]{index=0}  

  Machine Learning enables computers to **learn patterns from data** instead of being explicitly programmed.

  Key ideas:
  - Traditional programming = **Data + Rules → Output**  
  - Machine learning = **Data + Answers → Learn Rules (Model)**  
  - Model discovers patterns automatically.  
  - Example: recognizing apples vs oranges by learning features (color, shape).  
  - Training = discovering the rule (e.g., \(y = 5x + 1\)).  
  - Testing = applying the learned rule to new, unseen inputs.

  Why ML became popular:
  - Explosion of data from sensors, social media, transactions.  
  - Ability to find meaningful patterns at scale.  
  - Applications include self-driving cars, spam detection, recommendation systems.
## Types of Machine Learning Algorithms
  Based on:  
  - `W3P2 - Types of ML Algorithms.txt` :contentReference[oaicite:1]{index=1}  

  Three major ML categories:

  **1. Supervised Learning**  
  - Uses **labeled data**  
  - Two task types:  
    * Classification → discrete labels (spam / not spam)  
    * Regression → numeric prediction (house price)  
  - Workflow:
    1. Train on labeled historical data  
    2. Validate/test  
    3. Deploy model  

  **2. Unsupervised Learning**  
  - Works with **unlabeled data**  
  - Main tasks:
    * Clustering (customer segmentation)  
    * Dimensionality reduction (reducing 100 features → 10 features)  
    * Anomaly detection (fraud, outliers)  

  **3. Reinforcement Learning**  
  - Agent interacts with environment  
  - Learns **actions** that maximize **reward**  
  - Examples: game-playing AI, navigation robots, self-driving agents  

  Summary:
  - Supervised = learn from labels  
  - Unsupervised = discover structure  
  - Reinforcement = learn from rewards
## Types of Data in Machine Learning
  Based on:  
  - `W3P3 - Types of Data in ML.txt` :contentReference[oaicite:2]{index=2}  

  **1. Numerical (Quantitative)**  
  - **Discrete** → countable, whole numbers (e.g., number of students = 120)  
  - **Continuous** → real values (e.g., weight = 45.25 kg)

  **2. Categorical (Qualitative)**  
  - **Nominal** → no order (gender, color, car type)  
  - **Ordinal** → ordered (grades A > B > C, ratings 1–5)

  **3. Multidimensional Data**  
  - Each column = **feature**, each row = **sample**  
  - Structured data: tables  
  - Unstructured data: images, audio, text  
  - Semi-structured: JSON/XML wrapping unstructured content  

  Notes:
  - Unstructured data forms the **majority** (≈80%) of modern ML workloads.  
  - ML repositories like UCI provide open datasets for practice.
## K-Nearest Neighbors (KNN) Algorithm
  Based on:  
  - `W3P4 - KNN Algorithm.txt` :contentReference[oaicite:3]{index=3}  

  KNN is a **supervised**, **lazy-learning** algorithm.

  How it works:
  1. Choose K (typically an odd number)  
  2. Compute distance from test point to all training samples  
  3. Select the **K nearest neighbors**  
  4. Classification → majority vote  
  5. Regression → average of neighbors  

  Properties:
  - No training phase → stores all samples  
  - Useful as a baseline model  
  - Expensive for large datasets (computes distance to all samples)

  Similarity / Distance measures:
  - **Euclidean distance** → straight-line  
  - **Manhattan distance** → grid-based, absolute differences  
  - **Minkowski distance** → general form (m=1 → Manhattan; m=2 → Euclidean)  
  - **Hamming distance** → for binary/categorical strings  

  Feature scaling is essential:
  - Features with large numeric ranges dominate distance  
  - Use **normalization** (0–1 range)  
  - Or **standardization** (mean=0, std=1)

  Choosing K:
  - Trial and error  
  - Rule of thumb: \( k \approx \sqrt{n} \)  
  - Larger K → smoother decision boundary, less noise  
  - Smaller K → sensitive to noise, but more flexible  

  Limitations:
  - Slow for high-dimensional data (curse of dimensionality)  
  - Memory-heavy  
  - Sensitive to irrelevant features → requires preprocessing

  - Difference between supervised, unsupervised, reinforcement learning  
  - Classification vs regression vs clustering  
  - Data types: numerical (discrete/continuous) vs categorical (nominal/ordinal)  
  - Feature scaling essential for distance-based algorithms  
  - KNN details: distance metrics, majority voting, choosing K, lazy-learning

# WEEK 4 LINEAR REGRESSION, ERROR FUNCTION & GRADIENT DESCENT
## Linear Regression – Predicting Continuous Values
  Based on:  
  - `W4P1 - What is Linear Regression?.txt` :contentReference[oaicite:0]{index=0}  

  Linear Regression is a **supervised learning algorithm** used to predict **continuous numeric values** (e.g., price, height, weight, sales).

  Key ideas:
  - Uses labeled training data (X → y).  
  - Learns the **best-fit straight line** capturing the relationship between input(s) and output.  
  - Two types:
    * **Simple Linear Regression** → 1 feature  
    * **Multivariable Linear Regression** → multiple features  
  - Prediction equation (simple case):  
    \[
    \hat{y} = w_0 + w_1 x
    \]
  - \(w_0\): intercept (bias), \(w_1\): slope (weight).  
  - Goal: find \(w_0^*\) and \(w_1^*\) that minimize prediction error.

  Real-world examples:
  - Predicting sales based on advertising cost  
  - Predicting house price using area, rooms, location  
  - Predicting temperature, fuel consumption, demand forecasting  
## Error Function (Cost Function) – Why We Need It
  Based on:  
  - `W4P2 - What is Error Function in Linear Regression?.txt` :contentReference[oaicite:1]{index=1}  

  The model must measure how well the line fits the data.  
  This is done using the **Sum of Squared Errors (SSE)**:

  \[
  E = \sum (y - \hat{y})^2
  \]

  Interpretation:
  - Error = vertical distance between actual point and predicted line.  
  - Best-fit line = line that **minimizes the total squared error** across all data points.  
  - The error function is **convex** → U-shaped curve for one parameter; bowl-shaped surface for two parameters.

  Important distinctions:
  - **Minimum** of error = lowest cost value  
  - **Argmin** = parameter values (w₀, w₁) at which the minimum occurs  

  Visualization (from lecture):
  - Changing w₀ and w₁ generates many possible lines (L1, L2, …).  
  - The optimal line corresponds to the lowest point on the error surface (P1).  
## Gradient Descent – How Linear Regression Learns
  Based on:  
  - `W4P3 - Gradient Descent Algorithm.txt` :contentReference[oaicite:2]{index=2}  

  Gradient Descent is an optimization algorithm used to find the **optimal parameters** by **iteratively reducing the error**.

  Steps:
  1. Initialize weights \(w_0\), \(w_1\) randomly  
  2. Choose a learning rate \(L\)  
  3. Compute partial derivatives:
     \[
     \frac{\partial E}{\partial w_0},\; \frac{\partial E}{\partial w_1}
     \]
  4. Update weights:
     \[
     w_0 := w_0 - L \cdot \frac{\partial E}{\partial w_0}
     \]
     \[
     w_1 := w_1 - L \cdot \frac{\partial E}{\partial w_1}
     \]
  5. Repeat until convergence  

  Why learning rate matters:
  - **Too large** → overshoots minimum, diverges  
  - **Too small** → extremely slow learning  
  - Should be chosen carefully using experimentation  

  Convergence:
  - Reached when error difference between iterations is below small epsilon  
  - Or after fixed number of iterations  

  After convergence:
  - Use \( w_0^*, w_1^* \) in  
    \[
    \hat{y} = w_0^* + w_1^*x
    \]
    for new predictions.
## Multivariate Linear Regression
  Based on:  
  - `W4P4 - Multivariate Linear Regression.txt` :contentReference[oaicite:3]{index=3}  

  Extends simple regression to **multiple features**.

  Prediction equation:
  \[
  \hat{y} = w_0 + w_1 x_1 + w_2 x_2 + \dots + w_d x_d
  \]

  Introduces:
  - **Bias term:** set \(x_0 = 1\)  
  - **Vectorized form:**  
    \[
    \hat{y} = \mathbf{w}^T \mathbf{x}
    \]

  Benefits of vectorization:
  - Cleaner math  
  - Efficient computation via NumPy or other libraries  
  - Scales to large datasets  

  Gradient Descent for multivariate case:
  - Compute partial derivative for each \(w_j\)  
  - Update all weights **simultaneously**  
  - Continue until error minimized  

  Real-world use:
  - Predicting sales based on multi-channel advertising  
  - Predicting medical risk with dozens of biomarkers  
  - Predicting house price using multiple property features  
## Week 4 Learning Focus
  - Linear Regression = supervised learning for continuous values  
  - Best-fit line minimizes Sum of Squared Errors  
  - Error function is convex → gradient descent guaranteed to find global minimum  
  - Learning rate controls convergence behavior  
  - Multivariate regression uses vectorized dot-product form  
  - Gradient Descent scales naturally to multiple features  
  - Prediction = plug new input into learned regression equation

# WEEK 5 LOGISTIC REGRESSION, DECISION TREES & RANDOM FORESTS
## Logistic Regression – Classification with Probabilities
  Based on: `W5P1 - What is Logistic Regression?.txt` :contentReference[oaicite:0]{index=0}  

  Logistic Regression is a **supervised classification algorithm**, despite the name “regression.”

  Key ideas:
  - Used for **binary classification** (spam vs not spam, fraud vs non-fraud).  
  - Computes a **linear combination** of inputs → applies **sigmoid (logistic) function**.  
  - Output is a **probability** between 0 and 1.  
  - If probability ≥ 0.5 → class 1; else → class 0.  
  - Requires **numeric features** → text must be turned into numeric attributes first.

  Sigmoid function:
  \[
  g(z) = \frac{1}{1 + e^{-z}}
  \]
  - Squashes any real number to range 0–1.  
  - Makes outputs interpretable as probabilities.

  Why sigmoid?
  - Smooth curve → differentiable  
  - Maps weighted sum into probability space  
  - Suitable for gradient descent optimization  

  **Log-loss (Binary Cross Entropy)** is used instead of MSE:
  - Penalizes confident but wrong predictions heavily.  
  - Produces a **convex** optimization surface → easier to find optimal parameters.  
  - Works naturally with probabilistic outputs.

  Gradient Descent in Logistic Regression:
  - Initialize weights randomly  
  - Compute predictions using sigmoid  
  - Compute log-loss  
  - Update weights using gradients  
  - Repeat until convergence  

  Prediction for new data:
  - Use learned weight vector \( w^* \)  
  - Compute \( \hat{y} = g(w^* \cdot x) \)  
  - Apply 0.5 threshold  

  Common applications:
  - Spam detection  
  - Fraud detection  
  - Credit approval  
  - Medical risk classification  
## Decision Trees – Flowchart-Like Supervised Models
  Based on: `W5P2 - How does Decision Tree Work?.txt` :contentReference[oaicite:1]{index=1}  

  A decision tree is an **interpretable, rule-based** supervised learning algorithm.

  Structure:
  - **Root node** → first feature chosen  
  - **Decision nodes** → internal test conditions  
  - **Branches** → outcomes of tests  
  - **Leaf nodes** → final predictions  

  Why it's intuitive:
  - The model is a flowchart similar to human decision-making.  
  - Easy to visualize and explain to non-technical users.

  How a tree is built:
  1. Start with all features.  
  2. For each feature, compute **Gini Impurity**.  
  3. Choose the feature that gives **purest child nodes**.  
  4. Split the dataset.  
  5. Repeat recursively on each branch.  
  6. Stop when:
     - Node becomes pure  
     - Further split gives no improvement  
     - Max depth or stopping criteria is reached  

  Gini Impurity:
  \[
  G = 1 - \sum_{i=1}^{C} p_i^2
  \]
  - 0 → perfectly pure  
  - High value → mixed classes  

  Advantages:
  - Highly interpretable  
  - Works with numeric & categorical data  
  - No need for feature scaling  

  Disadvantages:
  - Easily overfits  
  - Sensitive to noisy data  
  - Makes local greedy decisions  

  Decision tree applications:
  - Customer churn prediction  
  - Spam detection  
  - Health risk analysis  
  - Loan approval  
## Random Forest – Many Trees Working Together
  Based on: `W5P3 - What is Random Forest?.txt` :contentReference[oaicite:2]{index=2}  

  Random Forest is an **ensemble** of many decision trees.

  Why it works:
  - Each tree sees a **bootstrap sample** (sampling with replacement).  
  - Each split considers a **random subset of features**.  
  - This randomness → diverse trees → better generalization.  

  Workflow:
  1. Create N random bootstrap datasets  
  2. Build a decision tree for each dataset  
  3. At each split, randomly select subset of features  
  4. Combine predictions:
     - Classification → majority vote  
     - Regression → average value  

  Benefits over a single tree:
  - Reduces overfitting significantly  
  - More stable and robust  
  - Less sensitive to noise  
  - Uses multiple “weak learners” to form a strong learner  

  Real-world applications:
  - Credit scoring  
  - Fraud detection  
  - Medical risk prediction  
  - Recommendation systems  
  - Crop yield prediction  
## Comparison: Logistic Regression vs Decision Tree vs Random Forest
  - **Logistic Regression**
    * Linear model  
    * Uses sigmoid for probabilities  
    * Great for explainability  

  - **Decision Tree**
    * Non-linear rules  
    * Very interpretable  
    * Prone to overfitting  

  - **Random Forest**
    * Ensemble of trees  
    * Reduces overfitting  
    * More accurate and stable  

  Summary:
  “Logistic regression outputs probabilities via sigmoid,  
  decision trees split data with rules,  
  random forests combine many trees to improve stability.”
## Week 5 Learning Focus
  - Logistic Regression → binary classification using sigmoid  
  - Log-loss → correct error measure for probabilistic outputs  
  - Gradient descent → training the model  
  - Decision Trees → interpretable rule-based models  
  - Gini impurity → measure of node purity  
  - Random Forest → ensemble method reducing overfitting  
  - Interpret differences and use cases for all three models

# WEEK 6 UNSUPERVISED LEARNING, CLUSTERING & K-MEANS
## What Is Unsupervised Learning?
  Based on: `W6P1 - Unsupervised Learning and Clustering.txt` :contentReference[oaicite:0]{index=0}  

  Week 6 focuses on how algorithms learn **patterns from data without labels**.

  Key ideas:
  - Unlike supervised learning (input + label), unsupervised learning only sees **X** (features), no **y**.  
  - Goal is to discover natural groups, structures, or hidden patterns.  
  - Useful when labels are expensive or unavailable (common in real-world data).  
  - Applications include exploratory analysis, anomaly detection, segmentation, and compression.

  Types of unsupervised learning:
  - **Clustering** (K-Means, DBSCAN, Hierarchical)  
  - **Dimensionality Reduction** (PCA, t-SNE, UMAP)  
  - **Association Rule Learning** (market basket analysis)

  Real-world examples:
  - Group customers by behavior  
  - Detect suspicious or unusual activities  
  - Organize unlabelled documents or images  
  - Compress images by grouping similar pixels
## Clustering Concepts
  Clustering groups similar objects into clusters based on **similarity or distance**.

  Key points:
  - Items in the same cluster are similar  
  - Items in different clusters are dissimilar  
  - No labels are provided → algorithm discovers the groups automatically  

  Example from lecture:  
  - Fruits (apples, bananas, oranges) with no labels  
  - Algorithm groups by size, color, shape

  Common clustering applications:
  - Customer segmentation  
  - Anomaly detection in system logs  
  - Image compression  
  - Traffic pattern grouping  
  - Document grouping  
## K-Means Clustering – How It Works
  Based on: `W6P2 - K-Means Clustering Algorithm.txt` :contentReference[oaicite:1]{index=1}  

  K-Means is the most widely used clustering algorithm.

  Main idea:
  - Partition data into **k** clusters  
  - Represent each cluster by its **centroid** (mean of its points)  
  - Assign each point to nearest centroid  
  - Recompute centroids → repeat until convergence

  Why we need feature scaling:
  - Distance-based methods are dominated by large-magnitude features  
  - Normalization or standardization is required before K-Means

  Two major steps:
  1. **Cluster assignment step**  
     * Assign each point to closest centroid (Euclidean distance)
  2. **Move centroid step**  
     * Update centroid to average position of its assigned points

  These steps repeat until:
  - No cluster assignment changes  
  - Centroids stop moving  
  - Algorithm has converged  

  Optimization objective (WCSSE):
  \[
  E = \sum_i \| x_i - M_{C_i} \|^2
  \]
  - Minimize distance between each point and its cluster centroid  
  - More compact clusters → lower error  

  Initialization:
  - Randomly choose **k** points as initial centroids  
  - Multiple random runs reduce chance of bad (local optimal) solutions  

  Selecting K:
  - **Elbow method** → choose k where error decrease slows down  
  - Domain knowledge (e.g., 4 T-shirt sizes → k=4)
## Other Clustering Algorithms
  Mentioned in Week 6:
  - **Hierarchical clustering** — builds a tree of clusters  
  - **DBSCAN** — density-based, finds irregular cluster shapes, identifies outliers  
  - These methods **do not require** specifying k upfront

# WEEK 7 ARTIFICIAL NEURAL NETWORKS, PERCEPTRON, MULTI-LAYER NETWORKS & BACKPROPAGATION
## What Is an Artificial Neural Network (ANN)?
  Based on:  
  - `W7P1 - Introduction to ANN.txt` :contentReference[oaicite:0]{index=0}  
  - `W7P2 - Single Layer ANN.txt` :contentReference[oaicite:1]{index=1}  
  - `W7P3 - Multi-layer ANN.txt` :contentReference[oaicite:2]{index=2}  

  An ANN is a **densely interconnected system of artificial neurons** inspired by biological neurons in the human brain.

  Core points:
  - ANN ≠ biological brain. ANN uses simple mathematical units; brain uses firing neurons and synapses.  
  - Each ANN neuron performs **weighted sum + activation**.  
  - ANN learns complex non-linear relationships without manual feature engineering.  
  - ANN can approximate extremely complex functions (universal approximation theorem).

  Typical architecture:
  - **Input layer**: holds raw feature values (no computation).  
  - **Hidden layer(s)**: perform weighted sums and activation.  
  - **Output layer**: produces final predictions (classification/regression outputs).  
  - ANN is a **function approximator** mapping input → output.
## Structure of a Neuron
  A neuron performs two key steps:
  - Compute **weighted sum**:  
    \[
    z = \sum_i w_i x_i + w_0 \cdot 1
    \]
  - Apply **activation function**:  
    \[
    o = g(z)
    \]

  Each neuron includes:
  - Inputs \(x_i\)  
  - Weights \(w_i\)  
  - Bias \(x_0 = 1\)  
  - Activation function (sigmoid, ReLU, step, etc.)  
  - Output value (real number)

  Analogy:  
  - Inputs = dendrites  
  - Weighted sum = signal integration  
  - Activation = neuron firing  
  - Output = signal sent to next neuron
## Activation Functions
  Activation introduces **non-linearity**, enabling networks to model complex behaviors.

  Common activation functions:
  - **Sigmoid**: outputs 0–1, smooth curve  
  - **Step function**: binary threshold  
  - **ReLU**: outputs max(0, x), simple & fast  
  - **Leaky ReLU**: prevents “dying ReLU”  
  - Activation is essential—without it, the entire network collapses into a linear model.
## Perceptron — Single-Layer ANN
  Based on: `W7P2 - Single Layer ANN.txt` :contentReference[oaicite:3]{index=3}  

  The perceptron is the simplest ANN:
  - **Inputs → one neuron → output**  
  - Activation = step function  
  - Output is **0 or 1**  
  - No hidden layers → only linearly separable problems

  Perceptron computation:
  - Weighted sum  
  - If > 0 → output = 1  
  - Else output = 0

  Perceptron training:
  - Compare prediction \( \hat{y} \) with true label \( y \)  
  - Update weights using gradient descent  
  - Learn decision boundary

  Example from lecture:
  - With inputs x₀=1, x₁=2, x₂=3 and weights, perceptron computes z then applies step function.  
  - Limited power → cannot solve XOR or curved boundaries.
## Multi-layer Neural Networks (MLPs)
  Based on: `W7P3 - Multi-layer ANN.txt` :contentReference[oaicite:4]{index=4}  

  Multi-layer networks address perceptron limitations.

  Structure:
  - Input layer (feature count = number of neurons)  
  - 1 or more hidden layers  
  - Output layer  
  - Each neuron fully connected to the previous layer  
  - Bias neurons added in each layer  

  Characteristics:
  - Can approximate any complex non-linear function  
  - Layers build **hierarchical features** (from simple → complex)  
  - Used for classification, regression, vision, NLP before deep learning architectures

  Example from lecture:
  - Input: 3 neurons  
  - Hidden: 4 neurons  
  - Output: 2 neurons (binary classification)  
  - Total weights = 26  
  - Output predicts class by comparing final neuron values.
## Feedforward Process
  Feedforward = computing predictions from left to right.

  Steps:
  - Put feature values into input layer  
  - Compute hidden layer values using weighted sums + activation  
  - Compute output layer values  
  - Output is \( \hat{y} \)

  Key principles:
  - No weight updates occur during feedforward  
  - Required for prediction and for computing loss  
  - Same mechanism used in classification (digit recognition example)
## Backpropagation
  Backpropagation = learning algorithm of neural networks.

  Steps:
  - Compare predicted \( \hat{y} \) with true \( y \) → compute error  
  - Compute gradients through chain rule  
  - Update weights from output layer → hidden → input  
  - Repeat for all samples until convergence (loss stops decreasing)

  Important concepts:
  - Requires differentiable activation functions  
  - Based on gradient descent updates  
  - Large errors → larger weight updates  
  - Backprop trains deep architectures layer-by-layer

  Common issues:
  - Vanishing/exploding gradients (motivation for ReLU, batch norm, deeper architectures)
## Digit Recognition (0–9) – Output Layer Design
  Based on Week 7 slides:
  - Recognizing digit images uses 10 possible classes  
  - Output layer must have **10 neurons**  
  - Each neuron has a probability for each digit  
  - Final digit = argmax of outputs

  Example:  
  Output vector = [0.01, 0.02, 0.85, 0.0, ...] → digit “2”

# WEEK 8 DEEP LEARNING, CNNs FOR VISION & RNN/LSTM FOR NLP
## What Is Deep Learning?
  Based on: `W8P1 - What is Deep Learning?.txt` :contentReference[oaicite:0]{index=0}  

  Deep Learning is a specialized branch of machine learning that uses **multi-layer neural networks** to automatically learn complex patterns from data.

  Key ideas:
  - Unlike traditional ML, DL **does not rely on manual feature engineering**.  
  - Each layer transforms data into increasingly abstract representations (data distillation).  
  - First layers learn **simple patterns** (edges), deeper layers learn **shapes**, and final layers learn **objects**.  
  - DL became powerful recently due to:
    * Better algorithms for training deep networks  
    * Large availability of labeled data  
    * GPUs/TPUs enabling massive parallel computation  
    * Open-source frameworks (TensorFlow, PyTorch, Keras)

  Analogy:
  - DL layers = steps in coffee processing (clean → roast → grind → brew) where each step transforms raw data into meaningful representation.
## Deep Learning for Computer Vision
  Based on: `W8P2 - Deep Learning for Computer Vision.txt` :contentReference[oaicite:1]{index=1}  

  DL revolutionized computer vision because CNNs automatically learn local features in images.

  Applications:
  - Image classification  
  - Object detection (bounding boxes)  
  - Image segmentation (pixel-level classification)  
  - Image super-resolution  
  - Image reconstruction & restoration  
  - Style transfer  
  - Image synthesis (GANs)

  Why CNNs instead of fully connected networks?
  - CNNs learn **local** spatial features (edges, corners, textures).  
  - ANNs treat all pixels equally and cannot exploit spatial locality.

  Key CNN properties:
  - **Translation invariance**  
    * Once a feature (e.g., an edge) is learned, it can be detected anywhere in the image.  
  - **Spatial hierarchy of features**  
    * First layer learns edges → next learns corners/curves → deeper layers learn shapes → final layers detect objects.

  Important architectures:
  - **AlexNet (2012)** — first major breakthrough on ImageNet.  
  - **VGGNet (2014)** — uses many small 3×3 filters; simple and effective.

  Core components:
  - **Convolutional layer**  
    * Learns filters that detect local patterns.  
    * Uses stride and padding to control output size.
  - **Pooling layer**  
    * Reduces spatial size (downsampling).  
    * No trainable weights.  
    * Max pooling keeps strongest activations.
  - **ReLU activation**  
    * Introduces nonlinearity to learn complex functions.
## Deep Learning for NLP: RNNs & LSTMs
  Based on: `W8P3 - Deep Learning for NLP.txt` :contentReference[oaicite:2]{index=2}  

  Text is sequential → DL models must understand **order**, **context**, and **long-range dependencies**.

  Applications:
  - Search autocomplete  
  - Machine translation  
  - Social media sentiment  
  - Chatbots and virtual assistants  
  - Document classification & summarization  
  - Voice assistants (speech-to-text & text-to-speech)  
  - Spam filtering  
  - Grammar correction (e.g., Grammarly)

  - RNNs
  - Designed for sequences; hidden state passes information across time steps.  
  - Can model short-term context well.  
  - Limitations:
    * Forget long-range dependencies (context disappears).  
    * Vanishing/exploding gradients during training.

  - LSTMs
  - Solve RNN limitations using **memory cells**.  
  - Three gates:
    * Forget gate (discard irrelevant info)  
    * Input gate (store new info)  
    * Output gate (expose relevant info)
  - Handle longer sequences and maintain meaning (e.g., “bank” in different contexts).  
  - Backbone of many NLP systems before Transformers.
## Text Representation: One-Hot Encoding vs Word Embeddings
  Key points from NLP lecture:
  - One-hot encoding:
    * Large sparse vectors  
    * No semantic relationships  
    * King = Apple (no similarity)
  - Word embeddings:
    * Dense vectors  
    * Learned from data  
    * Capture semantic similarity  
    * Words with similar meanings lie close in vector space

  Example:
  - Embedding vectors capture dimensions like gender, royalty, youthfulness  
  - Useful for tasks like translation, sentiment analysis, chatbots
## CNN & NLP Tutorial Integration
  Based on:
  - `Tutorial 6_CNN_RNN_Text Representation Answers.docx` :contentReference[oaicite:3]{index=3}  
  - `Tutorial 6 CNN_RNN_Text Representation Questions.docx` :contentReference[oaicite:4]{index=4}  

  Tutorial focus:
  - CNNs detect local spatial patterns using filters.  
  - Need multiple filters to detect different orientations/features.  
  - Pooling reduces size without losing key info.  
  - Bag-of-Words vs word embeddings differences.  
  - RNN struggles with meaning of words depending on context (“bank”) → LSTM handles context better.
## Week 8 Learning Focus
  - Deep learning is multi-layer representation learning.  
  - CNNs learn hierarchical spatial patterns → best for vision tasks.  
  - RNNs/LSTMs handle sequential dependencies → best for language tasks.  
  - Word embeddings capture semantic info beyond one-hot encoding.  
  - Pooling reduces computation without losing key features.  
  - Deep Learning succeeds due to data, compute, and improved algorithms.

# WEEK 9 GENERATIVE AI, TRANSFORMERS, LLMs, RAG & DIFFUSION MODELS
## Introduction to Generative AI (GenAI)
  Week 9 introduces Generative AI as a major shift from predictive ML models.  
  Unlike classification or regression, GenAI **creates new content**—text, images, audio, or code.

  Key concepts (from `W9P1 - Introduction to GenAI & Transformer Model.txt`): :contentReference[oaicite:0]{index=0}  
  - GenAI learns patterns from massive datasets and **generates entirely new outputs**.  
  - Examples: ChatGPT (text), DALL·E (images), Copilot (code).  
  - Analogy: GenAI works “like a **chef inventing new recipes** after tasting thousands of dishes.”  
  - Benefits: creativity, productivity, accessibility.  
  - Challenges: bias, hallucinations, misinformation, ethical concerns.
## Why Transformers Were a Breakthrough
  Transformers solved the limitations of RNNs/LSTMs.

  Key ideas:
  - RNNs process text **sequentially** → slow, difficult with long sequences.  
  - Transformers process sequences **in parallel**, capturing long-range dependencies efficiently.  
  - Introduced in the 2017 paper **“Attention Is All You Need.”**  
  - Foundation of all modern LLMs.

  Advantages:
  - Faster training due to parallelization.  
  - Better handling of long-range context.  
  - Scalable to billions of parameters.
## Attention Mechanism
  Attention helps models **focus on the most relevant parts** of the input sequence.

  Explanation (from lecture example):  
  - In the sentence “She is eating a green apple,” the model learns that **“eating” ↔ “apple”** is more important than “green.”  
  - Allows Transformers to identify contextual relationships regardless of distance.

  Why it matters:
  - Enables accurate translation, summarization, Q&A, and text generation.  
  - Core reason Transformers replaced RNNs in NLP.
## Transformer Architecture
  Transformers include:
  - **Encoder**: understands input context with self-attention.  
  - **Decoder**: generates outputs using masked attention to prevent seeing future words.  
  - **Positional encoding** adds sequence order information.

  Important variants:
  - **BERT** — bidirectional; best for understanding context.  
  - **GPT** — autoregressive, used for text generation.  
  - **BART/T5** — encoder–decoder for translation & summarization.  
  - **Multimodal models** — handle text+image (e.g., CLIP).
## Large Language Models (LLMs)
  Based on `W9P2 - LLMs and RAG.txt`: :contentReference[oaicite:1]{index=1}  

  What LLMs are:
  - Built on Transformer architecture.  
  - Trained on huge text datasets → understand patterns, semantics, context.  
  - Generate fluent, human-like text.

  Limitations:
  - Require huge data + GPUs/TPUs.  
  - Long training times.  
  - Domain-specific tasks require fine-tuning.  
  - **Hallucination**: confident but incorrect answers.

  Applications:
  - Chatbots, summarization, translation, tutoring, reasoning, search augmentation.
## Retrieval-Augmented Generation (RAG)
  RAG solves LLM hallucination and outdated knowledge issues.

  Concept:
  - Combines **retrieval** (search relevant info)  
          + **generation** (LLM producing output).  
  - LLM is “grounded” in retrieved documents.

  Workflow:
  - Collect knowledge base → chunk → embed → store in vector DB.  
  - Query converted to embedding → retrieve top-K relevant chunks.  
  - LLM generates answer **based on retrieved evidence**.

  Benefits:
  - Improves factual accuracy.  
  - Reduces hallucination.  
  - Provides context-specific relevance.  
  - Ideal for academic Q&A, enterprise knowledge systems.
## Large Vision Models (LVMs)
  From Week 9:  
  - Trained on large-scale visual datasets.  
  - Used for detection, segmentation, classification, image-to-text understanding.  
  - Foundation for image generation tasks.
## Diffusion Models & Stable Diffusion
  Based on `W9P3 - Image Generation & Stable Diffusion Model.txt`: :contentReference[oaicite:2]{index=2}  

  Diffusion models are the **state-of-the-art** in image generation.

  Core idea:
  - **Forward process**: gradually add noise to an image until it becomes pure noise.  
  - **Reverse process**: model learns to remove noise step-by-step to create new images.  
  - Like taking a dusty photo → learning to clean dust grain-by-grain.

  Why diffusion works:
  - Able to generate very high-quality, coherent images.  
  - Stable Diffusion → efficient, open-source, widely used in art and design.

  Applications:
  - Art & design  
  - Movie/game concept art  
  - Super-resolution  
  - Product design  
  - Medical imaging  
  - Education & visualization  
  - Historical reconstruction  
## Comparison of Advanced Models
  Summary from lecture end:
  - **RNN**: good for short sequences; suffers from forgetting.  
  - **LSTM**: handles long dependencies; slower.  
  - **Transformer**: parallel, scalable, long-range context.  
  - **LLMs + RAG**: state-of-the-art text systems; reduced hallucination.  
  - **CNNs** (Tutorial 6): best for spatial/visual features. :contentReference[oaicite:3]{index=3}  
  - **Diffusion Models**: high-quality image generation; computationally heavy.
## Tutorial 6 – CNNs, RNNs, LSTM & Text Representation
  Based on:  
  - `/mnt/data/Tutorial 6_CNN_RNN_Text Representation Answers.docx` :contentReference[oaicite:4]{index=4}  
  - `/mnt/data/Tutorial 6 CNN_RNN_Text Representation Questions.docx` :contentReference[oaicite:5]{index=5}  

  Key tutorial insights:
  - CNNs learn patterns via filters — horizontal, vertical edges, textures.  
  - Text must be converted to numbers:  
    * Bag-of-Words → counts words; no meaning.  
    * Embeddings → capture semantic similarity (“awesome” ≈ “good”).  
  - RNN vs LSTM handling context:  
    * RNN forgets long sequences (vanishing gradients).  
    * LSTM maintains memory with gates → better for long contexts (e.g., meaning of “bank”).
## Week 9 Learning Focus
  - Understand what GenAI is and how it differs from predictive ML.  
  - Know how Transformers work (attention, encoder/decoder).  
  - Master the role of BERT, GPT, BART, multimodal models.  
  - Recognize LLM challenges: hallucination, resource demands.

# WEEK 10 AI SYSTEMS, PIPELINE, MODEL MANAGEMENT & RESPONSIBLE AI
## What Makes an AI System Different from Traditional Software
  Week 10 establishes the foundational distinction between AI systems and traditional rule-based software.  
  Unlike fixed-logic programs, AI systems **learn from data**, **adapt to new patterns**, and **improve over time**.  
  They operate in dynamic, uncertain environments where handcrafted rules fail.

  Key ideas:
  - AI systems learn patterns from data instead of following fixed instructions.  
  - They can generalize to unseen situations and update through retraining.  
  - AI systems integrate multiple components: data pipelines, models, APIs, cloud infrastructure, monitoring systems.  
  - AI behaves like a “professional who learns from experience,” while traditional software acts like a “worker who follows instructions.” :contentReference[oaicite:3]{index=3}  
## AI Pipeline – The 9-Step End-to-End Process
  Week 10 introduces the **full AI system pipeline**, showing how real systems are built beyond Jupyter notebooks.

  The nine stages:  
  1. **Problem Framing**  
  2. **Data Collection**  
  3. **Data Preprocessing**  
  4. **Model Selection**  
  5. **Model Training**  
  6. **Validation**  
  7. **Model Evaluation**  
  8. **Deployment**  
  9. **Monitoring & Feedback Loop**  

  Highlights:  
  - The pipeline ensures scalability, reproducibility, and team collaboration.  
  - AI development **is not linear**; monitoring triggers retraining → new data collection → pipeline restarts.  
  - Mature companies use this pipeline to avoid stagnation at proof-of-concept.  
  - Most AI failures occur outside the model stage—during deployment or monitoring. :contentReference[oaicite:4]{index=4}  
## Problem Framing (Step 1)
  - Clarify whether the task is classification, regression, clustering, recommendation, etc.  
  - Identify business goals and measurable success metrics.  
  - Involve stakeholders early to avoid solving the wrong problem.  
  - Translate raw business questions into ML-friendly formulations.
## Data Collection (Step 2)
  - Gather data from logs, sensors, APIs, databases, social media, etc.  
  - Ensure legal compliance (PDPA, GDPR), consent, and anonymization.  
  - Raw data is filtered → curated dataset suited for training.  
  - Quality and relevance of data determine model success.  
## Data Preprocessing (Step 3)
  - Real-world data is messy — must be cleaned before training.  
  - Tasks include:  
    * Handling missing values  
    * Encoding categorical variables  
    * Normalizing / scaling numerical features  
    * Removing noise, inconsistencies, duplicates  
  - Preprocessing often takes more time than model training. :contentReference[oaicite:5]{index=5}  
## Model Selection (Step 4)
  - Choose ML / DL / generative models based on:  
    * Data type (images → CNNs, text → transformers)  
    * Interpretability needs  
    * Compute constraints  
    * Deployment environment (cloud, mobile, edge)  
  - Simpler models (LR, trees) are preferred when interpretability matters.
## Model Training (Step 5)
  - Model learns input → output relationships using labeled data.  
  - Loss minimization uses gradient descent and optimization.  
  - Good practices:  
    * Train/validation split  
    * Regularization  
    * Monitoring learning curves  
## Validation (Step 6)
  - Test model on validation data to check generalization.  
  - Avoid overfitting by comparing training vs validation performance.  
  - Perform hyperparameter tuning (learning rate, depth, layers).  
  - Use grid search, random search, or Bayesian optimization.  
  - k-fold cross-validation provides reliable estimates.  
## Model Evaluation (Step 7)
  - Final check on **unseen test data**.  
  - Classification metrics: precision, recall, F1, ROC-AUC.  
  - Regression metrics: MSE, RMSE, MAE, R².  
  - Evaluation metric depends on context (e.g., fraud → prioritize recall).  
## Deployment (Step 8)
  - The model is made accessible via:  
    * Online APIs (real-time predictions)  
    * Batch jobs (large periodic datasets)  
    * Edge devices (IoT, phones)  
  - Containers package model + code + dependencies → consistent execution.  
  - Deployment is the step where AI becomes usable, e.g., ChatGPT running on cloud servers. :contentReference[oaicite:6]{index=6}  
## Monitoring & Feedback Loop (Step 9)
  - Real-time systems must track:  
    * Data drift  
    * Concept drift  
    * Latency  
    * API errors  
    * Model confidence  
  - Feedback from users/humans enables retraining.  
  - Monitoring → collection → retraining → redeployment forms a continuous improvement cycle.
## Training Strategies (Batch, Online, Transfer Learning)
  - **Batch Learning**  
    * Train once on full dataset; useful when data is stable.

  - **Online / Incremental Learning**  
    * Model updates continuously as new data arrives.  
    * Ideal for fraud detection, IoT, real-time systems.

  - **Transfer Learning**  
    * Start from pretrained models (ResNet, BERT) → fine-tune for new tasks.  
    * Saves time, compute, and reduces data requirements.  
    * Efficient for domain adaptation. :contentReference[oaicite:7]{index=7}  
## Hyperparameter Tuning
  - Hyperparameters are external settings before training (learning rate, layers).  
  - Tuning greatly affects accuracy and stability.  
  - Methods:  
    * Grid Search  
    * Random Search  
    * Bayesian Optimization  
  - Goal: find optimal configuration for best performance.
## Feasibility & Data Readiness
  - Before building an AI system, check:  
    * Data availability + quality  
    * Legal restrictions  
    * Hardware resources  
    * Team capability  
  - Many organizations fail due to poor data maturity or lack of cross-team alignment—stuck at PoC stage.
## Fairness, Bias & Explainability
  - Bias sources: unbalanced data, proxy variables, historical inequalities.  
  - Mitigation strategies:  
    * Data balancing  
    * Bias-aware training objectives  
    * Post-processing corrections  
  - Explainability tools (SHAP, LIME) help understand model decisions in high-risk domains.  
## Scalability & Deployment Efficiency
  - Techniques include:  
    * Distributed training  
    * Model sharding  
    * Caching  
    * Load balancing  
    * Acceleration engines (TensorRT, ONNX Runtime)  
  - Required for large-scale, low-latency environments.
## A/B Testing
  - Compare model version A vs version B with real users.  
  - Use metrics (CTR, conversion, detection accuracy) to choose best variant.  
  - Must be randomized and fair to avoid confounding.
## Human-in-the-Loop (HITL)
  - Used when:  
    * Data is unclear  
    * Decision is high-stakes  
    * Case is rare/unseen  
  - AI handles confident predictions; humans review uncertain ones.  
  - Human feedback → improves model retraining.
## Model Compression
  - Makes models smaller and faster for mobile/edge deployment.  
  - Techniques:  
    * Quantization  
    * Pruning  
    * Knowledge distillation  
  - Example: DistilBERT = 40% smaller, 60% faster, ~97% performance.
## Week 10 Learning Focus
  - AI systems differ from rule-based software by learning and adapting.  
  - Understand all 9 pipeline steps deeply.  
  - Deployment + monitoring are critical for production success.  
  - Know training strategies, validation, evaluation metrics.

# WEEK 11 AI SYSTEM DEPLOYMENT, INFERENCE WORKLOADS & MLOps
## AI Deployment – What It Really Means
  Week 11 introduces deployment as the stage where a trained model leaves the notebook and enters a real system that serves actual users or applications.

  Deployment is defined as:
  - Making a trained model available to real-world users or systems to make predictions.
  - Moving from experimentation → production (closing the “AI production gap”).
  - Ensuring that the model runs reliably, consistently, and at scale.

  Key ideas:
  - Deployment is the operationalization of ML — not part of model training.

  - Connected directly to MLOps and DevOps infrastructure.
## Inference Workloads – Batch, Real-time, Streaming
  Week 11 stresses differences between inference modes, which are tested heavily in quizzes.

  - **Batch inference**
    * Processes large datasets at scheduled times (e.g., nightly credit-risk scoring).  
    * Not user-triggered; latency is not critical.

  - **Real-time inference**
    * Model responds within milliseconds.  
    * Used in autonomous driving, fraud detection, recommendations.  
    * Requires APIs, fast hardware, load balancing.

  - **Streaming inference**
    * Handles continuous, unbounded data flows (IoT sensors, stock ticks).  
    * Designed for evolving, high-frequency inputs.

  Core concept:
  - Inference is applying a trained model to new, unseen data — not training, not evaluation.
## MLOps & DevOps Roles in Deployment
  Week 11 clarifies which teams handle which responsibilities in real AI systems.

  - **MLOps engineers**
    * Automate deployment workflows.  
    * Build CI/CD pipelines for models.  
    * Manage model versioning, monitoring, and rollout (blue/green, canary).  
    * Ensure reproducibility across environments.

  - **DevOps teams**
    * Maintain compute infrastructure (servers, networks).  
    * Handle load balancers, autoscaling, containers, and runtime reliability.  
    * Ensure infrastructure supports inference requirements.

  - **Data scientists**
    * Build & validate models, not production systems.  
    * Collaborate with MLOps but do not run deployment pipelines.

  These distinctions appear directly in the quiz.
## Containers – Why They Are Required
  Week 11 explains that deploying ML models across machines requires runtime consistency.

  Containers (e.g., Docker):
  - Bundle **model + code + dependencies + environment**.
  - Ensure identical execution across dev, staging, and production.
  - Prevent “works on my machine” deployment failures.
  - Enable scalable deployment in Kubernetes and cloud infrastructure.

  Quiz-relevant idea:
  - Containers **do not** improve accuracy, GPU performance, or training speed.
## The AI Production Gap
  Defined as:
  - The challenge of moving from prototype notebooks to scalable, reliable production systems.
  - Caused by differences in environment, monitoring, version tracking, and engineering constraints.

  Week 11 emphasizes:
  - Successful deployment depends on engineering systems, not only model quality.
  - Many AI failures occur not at the model stage but at deployment & monitoring.
## Monitoring Phase – What to Check

  - **Concept drift** — when real-world relationships between features and target change.

  - **Degraded accuracy or rising false positive/negative rates**.  
  - **Latency spikes or API errors**.  
  - **Ethical or regulatory compliance issues**.

## Best Practices for Reliable Deployment

# WEEK 12 FAIRNESS, BIAS & EXPLAINABILITY IN AI
## Towards Effective Discrimination Testing for Generative AI
  Based on the paper: `/mnt/data/Week12_Paper1_Towards Effective Discrimination Testing for Generative AI.pdf`

  Week 12 highlights how generative AI introduces new complexity for fairness testing.

  Key points:

  - **Why GenAI fairness is difficult**
    * Outputs are dynamic, not fixed labels.  
    * Multi-turn interactions, user prompts, and context shifts make behaviour unpredictable.  
    * Standard fairness metrics from classification do not translate cleanly to generative models.

  - **Gaps in current testing**
    * Fairness tests often misalign with anti-discrimination regulations.  
    * One-shot tests miss problems appearing only in long conversations or varied prompts.  
    * Models can appear “fair” in controlled tests but behave differently under real-world usage.

  - **Improved testing strategy**
    * Scenario-based and multi-turn evaluations.  
    * Test for representational harms (stereotypes, biased associations), not only decision harms.  
    * Continuous monitoring after deployment—behaviour shifts over time.
## A Critical Survey on Fairness Benefits of Explainable AI
  Based on the paper: `/mnt/data/Week12_Paper2_A Critical Survey on Fairness Benefits of Explainable AI.pdf`

  This survey evaluates claims that explainability (XAI) improves fairness.

  Main ideas:

  - **Claim–reality mismatch**
    * Many claims about “XAI improves fairness” lack grounding in specific fairness definitions.  
    * XAI is often treated as universally beneficial without stakeholder-specific clarification.

  - **Seven fairness–XAI relationships**
    * Examples include: enabling human oversight, increasing trust, revealing bias sources, improving perceptions of fairness.  
    * Each varies by stakeholder (developer, user, regulator).

  - **Limitations**
    * XAI cannot solve data bias, proxy discrimination, or structural inequality.  
    * Explanations may even mislead if oversimplified or inaccurate.

  - **Best practice**
    * Specify which fairness goal and which stakeholder XAI supports.  
    * Use XAI as one component within broader fairness governance.
## Bias and Discrimination in AI: A Cross-disciplinary Perspective
  Based on the paper: `/mnt/data/Week12_Paper3_Bias and Discrimination in AI: a cross-disciplinary perspective.pdf`

  This paper expands fairness beyond technical metrics.

  Key concepts:

  - **Types of discrimination**
    * **Disparate treatment** — explicit unequal treatment.  
    * **Disparate impact** — indirect harm from seemingly neutral features.

  - **Sources of bias**
    * Biased datasets reflecting real-world inequality.  
    * Proxy variables that correlate with sensitive attributes.  
    * System-level feedback loops that amplify discrimination.

  - **Cross-disciplinary insight**
    * Fairness must consider legal norms, social context, and power structures.  
    * Purely technical fixes are insufficient if system design reinforces inequality.

  - **Practical takeaway**
    * Address bias early: problem framing → data collection → feature design → deployment monitoring.
## Algorithmic Fairness
  Based on the paper: `/mnt/data/Week12_Paper4_Algorithmic Fairness.pdf`

  This paper introduces formal fairness definitions and trade-offs.

  Core ideas:

  - **Fairness metrics**
    * **Statistical parity** — equal decision rates across groups.  
    * **Equalized odds** — equal true/false positive rates.  
    * **Predictive parity** — equal predictive accuracy.  
    * **Calibration** — equal reliability of predicted probabilities.

  - **Trade-off problem**
    * Many fairness definitions cannot be satisfied simultaneously.  
    * Choosing one definition reflects value judgments and domain constraints.

  - **Implications for deployment**
    * Fairness constraints may reduce accuracy but support ethical/regulatory goals.  
    * Must choose fairness definition aligned with the specific application (e.g., loans vs security).

# Cheat sheet
  - **Artificial Intelligence**
    - **Definition**: (human) perceive, think/reason/learn, and act. -> (Machines) Perceive, analyze/cumpute/learn, act.
    - **Subfields**: ML/DL, CV, NLP, Expert Systems, Speech Processing, Robotics (Active Camara Coordination).
    - **Narrow AI**: task-specific (Siri, Translate, Face ID). **General AI**: human-like adaptability (still theoretical).
    - **Landmarks**: Deep Blue (1997, rule based search and evaluation), DARPA Cars (2005, autonomous driving), Watson (2011, Jeopardy), AlphaGo (2016, reinforcement, Go champion), OpenAI Five (2019, esports), GPT-3 (2020, 175B LLM), AlphaFold (2021, protein folding).
    - **Rule-Based vs ML**: Rule-based = human-crafted rules, ML = system learns rules/patterns from data
  - **Types of Machine Learning**
    - **Supervised**: labeled → Classification (spam, fraud) & Regression (house price).
    - **Unsupervised**: unlabeled → Clustering (K-means, DBSCAN), Dim.Reduction (PCA, t-SNE), Anomaly detection, Association rules (market basket).
    - **Reinforcement**: agent learns by actions + rewards, e.g., game bots, robotics.
    - **Tasks**: Classification, Regression, Clustering, Dim.Reduction, Anomaly Detection.
  - **Data types & Preprocessing**:
    - **Numerical**: Discrete (# of bedrooms), Continuous (temperature). **Categorical**: Nominal (blood type), Ordinal (shirt size).
    - **Structured** (tables), **Unstructured** (images, text), **Semi-structured** (JSON, XML).
    - **Scaling**: **Standardization**: `(x–μ)/σ` → mean 0, σ 1. **Normalization**: `(x–min)/(max–min)` → range 0–1.
    - **WHY Scaling** The ML algorithms takes only the magnitude of features neglecting the units - there is a chance that higher weightage is given to features with higher magnitude.
    - Without scaling, features with higher magnitudes can dominate distance calculations and optimization.
    - **Euclidean**: `√Σ(xᵢ–yᵢ)²`. **Manhattan**: `Σ|xᵢ–yᵢ|`. **Minkowski**: `(Σ|xᵢ–yᵢ|ᵐ)¹ᐟᵐ`. **Hamming**: count differences (categorical/binary).
  - **KNN Algorithm**
    - **Steps**: choose K → compute distances new with all training data → sort the distance → pick K nearest → Determine their class value → majority vote (classification) / average (regression)
    - **Sensitivity**: Smaller K = high variance/noisy, Larger K = smoother, less noise
    - **Notes**: no training phase, memory-based (lazy learner). Bad with irrelevant features & high dimension (curse of dimensionality). MUST scale features.
  - **Linear Regression**
    - **Equations**: `ŷ = w₀ + Σ wᵢxᵢ`. **Error (cost) (SSE/MSE)**: `E = (1/2N) Σ(y – ŷ)²`.
    - **Gradient Descent**: `wⱼ ← wⱼ – η ∂E/∂wⱼ` = `wⱼ + η (1/N) Σ(y – ŷ)xⱼ`.
    - **Evaluation**: MAE `avg|y–ŷ|` (easy to interpret), MSE `avg(y–ŷ)²` (penalizes large errors), RMSE `√MSE` (same units as target), R² `1-SSE/SST,SSE=sum(y-ŷ)²,SST=sum(y-ȳ)²` (explained var, 1->perfect).
    - **Limitations**: assumes linearity, sensitive to outliers, multicollinearity issues.
    - **Learning Rate**: Too Large - overshoot minimum and fail to convergence. Too small - more time to converge. `trial-and-error` to choose a nominal value of 𝐿.
  - **Logistic Regression**
    - **Sigmoid (logistic)**: `g(z) = 1/(1 + e^(–z))`. Output ∈ (0, 1). **Predict**: `ŷ = g(W·xᵀ)` class = 1 if `g(z) ≥ threshold`.
    - **Log Loss**: `-[y log ŷ + (1–y) log (1–ŷ)]`. **Gradient Update**: `wⱼ ← wⱼ + η (y – ŷ)xⱼ`.
    - **Applications**: spam detection, fraud detection, medical diagnosis, credit approval.
    - **Why log loss not MSE**: better for probability predictions, smoother optimization, stronger penalty for confident wrong.
  - **Decision Trees (CART)**
    - Flowchart helps make decisions step by step. Used for classification and regression. Intuitive and easy to understand.
    - **Splits**: At each node, choose the best feature and split point - picks the feature that maximally decreases impurity.
    - `Gini=1–Σpᵢ²`, `Entropy=-Σpᵢ log pᵢ`. **Gini** 0→all items belong to one class (pure), higher value→more mix (impure).
    - **Parts**: Root, decision nodes, branches, leaves, sub-tree.
    - **Pros**: Interpretable, handles num+cat, no scaling needed.
    - **Cons**: Overfitting if not limited in depth or size (need depth limit / pruning), high variance and sensitive to Small Changes in Data, greedy/local splits not considering whether it leads to the best overall tree.
    - **Stopping criteria**: max depth reached, min samples per leaf, no improvement in impurity.
  - **Random Forest**
    - Multiple Decision Trees together to make a better decision. Trains many trees on random subsets of data and features.
    - Overfitting from individual trees is smoothed out by the ensemble. many opinions > one biased expert.
    - Each tree becomes a “weak learner” Individually, these trees may overfit or be noisy. But collectively, when combined in the forest, their strengths complement each other.
    - **Steps**:
      1. Bootstrap sampling (with replacement). Randomly pick different subsets of training data.
      2. Construct a Decision Tree on each subset of data.
      3. For each split, only consider a random subset of features (not all).
      4. Predict by majority vote (classification) / average (regression).
    - **Advantage**: reduces overfitting, increases stability, handles missing data better.
    - **Applications**: healthcare: disease risk, Finance: credit scoring / fraud detection, Retail: customer churn, recommend.
  - **K-Means Clustering**
    - It aims to partition the data into K distinct, non-overlapping clusters. Each cluster is defined by its centroid - the average of all points in the cluster.
    - Useful for exploration, preprocessing, segmentation, anomaly detection, pattern discovery, and more.
    - **User cases**: Group customers. Detect unusual behavior or potential intrusions. Reduce the size of images.
    - **Steps**:
      1. Initialize K centroids (random). Sensitive to starting points -> Run K-means multiple times, compute the objective function and choose the run with the lowest value.
      2. **Cluster assignment**: Assign data points to closest cluster center.
      3. **Move centroid**: Change the cluster center to the average of its assigned points.
      4. Repeat 2-3 until convergence (no centroid change).
    - **Optimization Objective**: The squared Euclidean distance between points and centroids: `(1/N) Σ‖xᵢ – Mᵢ‖²`.
    - **Choosing K**: Elbow method (plot WCSSE vs K) → optimal K where WCSSE drops slowly.
    - **WCSSE** `Σ‖xᵢ – Mᵢ‖²` (compactness). Lower is better -> indicates compact clusters.
    - **Silhouette score** `(b–a)/max(a,b), ∈ [–1,1]`, `> 0.5 = good clustering`. where `a` means average distance to other points in the same cluster, `b` means average distance to points in the nearest different cluster. (cohesion and separation) comparing the average distance of points to their own and the nearest cluster, visual plots.
    - **Visual inspection** = scatter plots. Look for: clear boundaries between clusters, compact grouping within clusters.
    - **Properties**: needs feature scaling, random init → multiple runs, sensitive to outliers, spherical clusters, multiple runs for best result.
  - **Confusion Metrics**
    - TP: Model predicted Positive, and it was correct. TN: Model predicted Negative, and it was correct. FP: Model predicted Positive, but it was wrong. FN: Model predicted Negative, but it was wrong.
    - `Accuracy = (TP+TN)/All`. How often the model is correct overall. In imbalanced datasets, high accuracy can be misleading → use Precision/Recall/F1..
    - `Precision = TP/(TP+FP)`. Accuracy of positive predictions.
    - `Recall = TP/(TP+FN)`. Of the actual positives, how many were correctly identified? High Recall → few FN.
    - `F1 = 2·(Prec·Recall)/(Prec+Recall)`. Weighted mean of Precision and Recall. Balances both.
    - Confusion matrix = `[[TP, FP],[FN, TN]]`.
    - Precision ↑ → FP ↓, Recall ↑ → FN ↓, threshold ↑ → TP↓FP↓FN↑ → Precision ↑ Recall↓
  - **ANN and DL** ANN neuron parts = `weights, bias, activation`.
    - **Activation**: Sigmoid (0–1), ReLU (max(0,z)), tanh (–1→1), Step (binary).
    - Backprop requires differentiable activations. Vanishing gradients: sigmoid/tanh can cause; ReLU alleviates.
    - **Perceptron**: single-layer, step activation, solves linearly separable problems only.
    - **MLP (Multi-layer ANN)**: hidden layers learn hierarchical representations. More layers = capture non-linear patterns.
    - **CNN**: Convolution learns **edges → textures → shapes → objects**. Pooling (max/avg) reduces dimension. Translation invariance. Good for images.
    - **CNN Layers**: Conv → ReLU → Pool → FC. **Tasks**: object detection, segmentation, super-resolution, style transfer.
    - **RNN**: maintains hidden state for sequence data; struggles with long-term dependencies (vanishing gradient).
    - **LSTM**: long-term memory via input/forget/output gates; handles long sequences (text, speech).
    - **DL Advantages**: automatic feature learning, high accuracy on vision/NLP. **Limitations**: large data+compute, difficult interpretability.
    - **Explainability (XAI)**: tools (SHAP/LIME/Grad-CAM) help interpret models but do not remove inherent bias.
  - **GenAI and Modern AI Systems**
    - **Generative AI**: produces new text (ChatGPT), images (DALL·E/Stable Diffusion), audio, code (Copilot). Learns distributions, not rules.
    - **Transformer Architecture**: Attention-based. Parallelized. Replaces recurrence. **Self-attention** weights relevance across tokens. **Paper**: *Attention is All You Need*.
    - **GPT**: autoregressive, predicts next token left→right.  
      **BERT**: bidirectional, masked language modeling (context both sides).
    - **LLM Issues**: hallucination, bias, lack of grounding, requires huge data, domain generality ≠ factual accuracy.
    - **RAG (Retrieval-Augmented Generation)**: retrieves relevant documents → LLM generates final answer. Reduces hallucination, increases factuality.
    - **Diffusion Models**: **Forward process**: add noise step-by-step → pure noise. **Reverse process**: gradually denoise → generate new image. **Used in**: DALL·E, Stable Diffusion, Midjourney.
  - **AI System** Problem framing → Data collection → Preprocessing → Model selection → Training → Validation → Evaluation → Deployment → Monitoring (feedback loop)
    - **Purpose**: structured end-to-end pipeline to move from business need → ML solution → production system.
    - **Validation vs Evaluation**: validation = tuning; evaluation = final unseen test.
    - **Success Metric Selection**: classification → precision/recall/F1; regression → MSE/RMSE/R².
  - **Deployment, Inference & MLOps**
    - **Inference Types**: **Batch**: periodic jobs (e.g., daily risk scoring). **Real-time**: ms latency (fraud detection, recommendations). **Streaming**: continuous flow (IoT sensors, stock feeds).
    - **Deployment**: model exposed via **API endpoint**. Must handle scaling, reliability, latency.
    - **Containers (Docker)**: bundle **model + code + dependencies** → consistent runtime across environments.
    - **Edge**: low-latency, offline operation (IoT, mobile). **Cloud**: scalable, centralized computing. **Hybrid**: cloud training + edge inference (common in production).
    - **MLOps Principles**: `CI/CD for models (automated training/testing/deployment)`. `Model/data/feature versioning`. `Automated monitoring, retraining triggers, rollback safety`. `Governance, reproducibility, lineage tracking`.
    - **Prediction Servers**: load-balanced instances handling user queries.
  - **Monitoring, Drift & Reliability**
    - **Model Degradation**: concept drift, data drift, software bugs, API mismatches.
    - **Data Drift**: input feature distribution changes (e.g., users now shop overseas more often). **Concept Drift**: relationship (X → y) changes (e.g., fraud patterns evolve).
    - **Drift Signals**: sudden accuracy drop, increased FPs/FNs, confidence ↓, latency ↑, API error spikes.
    - **Actions**: trigger retraining, update training data, recalibrate thresholds, introduce HITL for low-confidence predictions.
    - **HITL (Human-in-the-Loop)**: human reviews borderline or uncertain predictions → safety in fraud, healthcare, legal.
    - **Version Control**: track data, model weights, metrics, configs to ensure reproducibility.
    - **Monitoring Tools**: track latency, drift, errors, throughput. **Online APIs**: enable real-time ML predictions integrated into apps or devices.
  - **Others**
    - **Bias Sources**: sampling bias, proxy variables, label bias.
    - **Fairness Metrics**: statistical parity, equalized odds, calibration across groups.
    - **Mitigation**: `Pre-processing: reweighting, resampling`. `In-processing: fairness-aware loss functions`. `Post-processing: adjust decision thresholds`.
    - **Explainability**: helps interpretation but does not eliminate bias
    - **Hyperparameter Tuning**  `Grid Search (combinations)` `Random Search (efficient sampling)` `Bayesian Optimization (probabilistic search)`
    - **Training Modes**: **Batch Training**: periodic full retrains. **Online / Incremental**: update model continuously as new data arrives. **Transfer Learning**: adapt a pre-trained model to a new domain with limited data.
