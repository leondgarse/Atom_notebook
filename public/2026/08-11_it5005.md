## Propositional Logic Aug2026
  - **Logical Connectives (Truth Table)**
    | P | Q | ¬P | P ∧ Q | P ∨ Q | P ⇒ Q | P ⇔ Q |
    |---|---|----|-------|-------|-------|-------|
    | F | F | T  | F     | F     | T     | T     |
    | F | T | T  | F     | T     | T     | F     |
    | T | F | F  | F     | T     | F     | F     |
    | T | T | F  | T     | T     | T     | T     |

    *P ⇔ Q is true means P ⇒ Q is true AND Q ⇒ P is true*
  - **Logic: Historical View**
    - **500–300 BCE:** Socrates, Plato, Aristotle – Syllogisms, Modus Ponens
    - **~300 BCE:** Stoic schools – Systematic inference rules, deduction theorems
    - **1500–1900 CE:** Leibniz, Boole, Schroder – Translation of logical inferences to mathematical processes, enabling automated reasoning
  - **Syllogism Example**
    - Premise 1: All men are mortal
    - Premise 2: Socrates is a man
    - Conclusion: Socrates is mortal
  - **Rules of Inference**
    - **Modus Ponens:** If P ⇒ Q and P are true, then Q is true
    - **Modus Tollens:** If P ⇒ Q and ¬Q are true, then ¬P is true
    - **Elimination:** If P ∨ Q and ¬Q are true, then P is true
    - **Transitivity:** If P ⇒ Q and Q ⇒ R are true, then P ⇒ R is true
    - **Generalization:** If P is true, then P ∨ Q is true
    - **Specialization:** If P ∧ Q is true, then P is true
  - **Example Problem (Glasses)**
    - **Given:**
      - a. Newspaper in kitchen ⇒ glasses on kitchen table
      - b. Glasses on kitchen table ⇒ saw at breakfast
      - c. ¬(saw at breakfast)
      - d. Newspaper in living room ∨ Newspaper in kitchen
      - e. Newspaper in living room ⇒ glasses on coffee table
    - **Query:** Glasses on coffee table?
    - **Answer:** True (via Modus Tollens + Elimination + Modus Ponens)
  - **Expert Systems Architecture** Subject Matter Expert → Knowledge Engineer → **Knowledge Base, Inference Engine, Explanation System, User Interface** → User (Query ↔ Advice)
  - **Agenda**
    - **Representation:** Propositional Forms, CNF, Definite Clauses
    - **Inferencing:** Model Checking, Proof-by-Contradiction (Resolution Refutation), Proof-by-Deduction (Forward Chaining, Backward Chaining)
  - **Knowledge-Based (KB) Agents**
    - **Knowledge Base:** Domain-specific rules & facts (set of sentences in formal language)
    - **Inference Engine:** Domain-independent reasoning algorithms
  - **Rule Syntax**
    - IF `<antecedent>` THEN `<consequent>`
    - Antecedent = Condition/Premise; Consequent = Conclusion/Action/Outcome
    - **Multiple Antecedents:** IF (A1 ∧ A2 ∧ … ∧ An) THEN C (Conjunction) ; IF (A1 ∨ A2 ∨ … ∨ An) THEN C (Disjunction)
  - **Propositional Logic (PL)**
    - **Syntax:** Sentences → Atomic (`True`, `False`, `P`, `Q`, …) or Complex (using ¬, ∧, ∨, ⇒, ⇔)
    - **Operator Precedence:** ¬ > ∧ > ∨ > ⇒ > ⇔
    - **Semantics:** Truth tables, Models, Logical Equivalence, Validity, Satisfiability, Entailment
  - **Model (Possible World)**
    - An assignment of truth values to all variables in a sentence
    - Number of models = 2ⁿ (n = number of propositional symbols)
    - **M(α):** Set of all models where sentence α is true
  - **Validity / Tautology:** True in all models (e.g., P ∨ ¬P)
  - **Contradiction:** False in all models (e.g., P ∧ ¬P)
  - **Satisfiable:** True in at least one model (e.g., P ∧ Q, P ∨ Q)
  - **Logical Equivalence (≡):** M(α) = M(β), or α ⇔ β is a tautology
  - **Standard Logical Equivalences**
    - Commutativity: (α ∧ β) ≡ (β ∧ α), (α ∨ β) ≡ (β ∨ α)
    - Associativity: ((α ∧ β) ∧ γ) ≡ (α ∧ (β ∧ γ)), ((α ∨ β) ∨ γ) ≡ (α ∨ (β ∨ γ))
    - Double Negation: ¬(¬α) ≡ α
    - Contraposition: (α ⇒ β) ≡ (¬β ⇒ ¬α)
    - Implication Elimination: (α ⇒ β) ≡ (¬α ∨ β)
    - Biconditional Elimination: (α ⇔ β) ≡ ((α ⇒ β) ∧ (β ⇒ α))
    - De Morgan: ¬(α ∧ β) ≡ (¬α ∨ ¬β), ¬(α ∨ β) ≡ (¬α ∧ ¬β)
    - Distributivity: (α ∧ (β ∨ γ)) ≡ ((α ∧ β) ∨ (α ∧ γ)), (α ∨ (β ∧ γ)) ≡ ((α ∨ β) ∧ (α ∨ γ))
  - **CNF (Conjunctive Normal Form) Grammar**
    - CNFSentence → Clause₁ ∧ … ∧ Clauseₙ
    - Clause → Literal₁ ∨ … ∨ Literalₘ
    - Literal → Symbol | ¬Symbol
    - Symbol → P | Q | R | …
    - **Facts:** Single positive literal (e.g., P)
    - **Unit Clauses:** Single literal (e.g., P, ¬Q)
  - **Conversion to CNF Steps**
    1. Biconditional Elimination: α ⇔ β → (α ⇒ β) ∧ (β ⇒ α)
    2. Implication Elimination: α ⇒ β → ¬α ∨ β
    3. Move ¬ inwards (to literals only)
    4. Distributivity
  - **Definite Clauses & Horn Clauses**
    - **Definite Clause:** Exactly one positive literal (e.g., ¬X ∨ Y ≡ X ⇒ Y)
    - **Horn Clause:** At most one positive literal (e.g., ¬X ∨ ¬Y, ¬X ∨ Y, X)
    - **Fact:** Horn clause with single positive literal (X ≡ True ⇒ X)
    - **Goal Clause:** Horn clause with no positive literal (¬X ∨ ¬Y ≡ X ∧ Y ⇒ False)
  - **Entailment (⊨)**
    - α ⊨ β iff M(α) ⊆ M(β) iff (α ⇒ β) is a tautology iff (α ∧ ¬β) is unsatisfiable
    - **Violated when:** There exists a model where α is true and β is false (α ∧ ¬β is satisfiable)
  - **Equivalence vs Entailment**
    - Equivalence: M(α) = M(β)
    - Entailment: M(α) ⊆ M(β)
  - **Soundness & Completeness of Inference**
    - **Sound:** If KB ⊢ᵢ α, then KB ⊨ α (doesn't make stuff up)
    - **Complete:** If KB ⊨ α, then KB ⊢ᵢ α (derives all entailed sentences)
  - **Inferencing Methods**
    - **Model Checking (Brute-Force):** Exhaustive truth-table enumeration
    - **Proof by Deduction:** Forward/Backward Chaining (for Horn clauses)
    - **Proof by Contradiction:** Resolution Refutation (for CNF)
  - **Model Checking Algorithm**
    - Check if M(KB) ⊆ M(Query) using truth-table enumeration
    - Complexity: O(2ⁿ) – exponential in number of symbols
    - **Example:** KB = {P, P ⇒ Q}, Query = Q → Entails (True)
    - **Example:** KB = {P ⇒ Q}, Query = Q → Does NOT entail (False)
  - **Proof by Deduction (Inference Rules)**
    - Modus Ponens: (α ⇒ β, α) / β
    - AND-Elimination: (α ∧ β) / α
    - Biconditional Elimination/Introduction
  - **Resolution Rule (for CNF)**
    - (Literal₁ ∨ Clause₁) ∧ (¬Literal₁ ∨ Clause₂) ⊨ (Clause₁ ∨ Clause₂)
    - **Examples:**
      - (X ∨ Y) ∧ (¬X) ⊨ Y
      - (X ∨ Y) ∧ (¬X ∨ Y) ⊨ Y
      - (X ∨ Y ∨ Z) ∧ (X ∨ ¬Y ∨ Z) ⊨ (X ∨ Z)
      - X ∧ ¬X ⊨ □ (empty clause – contradiction)
  - **Proof by Contradiction (Refutation)**
    - KB ⊨ α iff KB ∧ ¬α is UNSAT (contradiction)
    - Algorithm: Convert KB ∧ ¬α to CNF, repeatedly resolve until empty clause is found
    - If empty clause found → α is entailed
    - If no new clauses generated → α is not entailed
  - **Forward Chaining (Data-Driven)**
    - Start with known facts; repeatedly apply rules whose premises are all true; add conclusions until query is proved
    - **Example:** KB = {A, B, A∧B⇒L, L∧M⇒P, P⇒Q} → Query Q → True
  - **Backward Chaining (Goal-Driven)**
    - Start with query; find rules whose conclusion matches query; recursively prove antecedents
    - **Issues:** Naïve implementation cannot handle cycles (e.g., P⇒Q, Q⇒R, R⇒P)
    - **Homework:** How to eliminate cycles? (Use a visited set to avoid infinite recursion)
  - **Limitations of Propositional Definite Clauses**
    - Cannot model uncertainty
    - Cannot handle complex relations efficiently (e.g., Wumpus world: Breeze ↔ Pit in neighbours, Stench ↔ Wumpus)
  - **Summary**
    - **Representation:** Syntax & Semantics of PL, CNF, Horn Clauses
    - **Inferencing Methods:**
      - Model Checking (complete but exponential)
      - Resolution (complete for CNF)
      - Forward/Backward Chaining (efficient for Horn clauses)

# Propositional Logic (Supplementary) – Logic Jan2024
## Logical Form and Logical Equivalence
- **Reference:** Epp's Chapter 2 – The Logic of Compound Statements
- **Statement (Proposition):** A sentence that is true or false, but not both.
- **Statement Form (Propositional Form):** Expression made up of statement variables and logical connectives that becomes a statement when actual statements are substituted.
- **Logical Connectives & Truth Tables**
  - **Negation (~p / ¬p):** Not p
  - **Conjunction (p ∧ q):** p and q
  - **Disjunction (p ∨ q):** p or q
  - **Order of operations:** ~ (first) > ∧, ∨ (coequal) > →, ↔ (last). Use parentheses to disambiguate.
- **Logical Equivalence (≡):** Two statement forms are logically equivalent iff they have identical truth values for all substitutions.
  - To prove **not equivalent**: (1) Truth table – find a row with differing values; (2) Counter-example – concrete statements with opposite truth values.
- **De Morgan’s Laws:**
  - ~(p ∧ q) ≡ ~p ∨ ~q
  - ~(p ∨ q) ≡ ~p ∧ ~q
  - *Can be extended to more than two variables.*
- **Tautology:** Always true (e.g., p ∨ ~p)
- **Contradiction:** Always false (e.g., p ∧ ~p)
- **Summary of Logical Equivalences (Theorem 2.1.1):**
  | Law                    | Formula                                                          |
  | ---------------------- | ---------------------------------------------------------------- |
  | Commutative            | p ∧ q ≡ q ∧ p; p ∨ q ≡ q ∨ p                                     |
  | Associative            | (p ∧ q) ∧ r ≡ p ∧ (q ∧ r); (p ∨ q) ∨ r ≡ p ∨ (q ∨ r)             |
  | Distributive           | p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r); p ∨ (q ∧ r) ≡ (p ∨ q) ∧ (p ∨ r) |
  | Identity               | p ∧ true ≡ p; p ∨ false ≡ p                                      |
  | Negation               | p ∨ ~p ≡ true; p ∧ ~p ≡ false                                    |
  | Double Negative        | ~(~p) ≡ p                                                        |
  | Idempotent             | p ∧ p ≡ p; p ∨ p ≡ p                                             |
  | Universal Bound        | p ∨ true ≡ true; p ∧ false ≡ false                               |
  | Absorption             | p ∨ (p ∧ q) ≡ p; p ∧ (p ∨ q) ≡ p                                 |
  | Negation of true/false | ~true ≡ false; ~false ≡ true                                     |
## Conditional Statements
- **Conditional (p → q):** "If p then q" – false only when p is true and q is false.
  - p = hypothesis/antecedent; q = conclusion/consequent.
  - **Vacuously true:** When p is false, p → q is true regardless of q.
- **Implication Law:** p → q ≡ ~p ∨ q
- **Negation of Conditional:** ~(p → q) ≡ p ∧ ~q
- **Contrapositive:** p → q ≡ ~q → ~p (logically equivalent)
- **Converse:** q → p (not equivalent to original)
- **Inverse:** ~p → ~q (not equivalent to original)
- **Only If:** "p only if q" means p → q (or ~q → ~p)
- **Biconditional (p ↔ q):** "p if and only if q" – true when p and q have the same truth values.
- **Necessary and Sufficient Conditions:**
  - r is **sufficient** for s: r → s
  - r is **necessary** for s: s → r (or ~r → ~s)
  - r is **necessary and sufficient** for s: r ↔ s
## Valid and Invalid Arguments
- **Argument:** Sequence of statements ending with a conclusion.
  - **Premises:** All statements except the final one.
  - **Conclusion:** Final statement (preceded by `•`).
- **Valid Argument Form:** Whenever premises are all true, the conclusion is also true.
  - **Critical row:** A row in the truth table where all premises are true.
  - **Invalid if:** There exists a critical row where the conclusion is false.
- **Rules of Inference (Valid Argument Forms):**
  | Rule                             | Form                              |
  | -------------------------------- | --------------------------------- |
  | **Modus Ponens**                 | p → q, p / • q                    |
  | **Modus Tollens**                | p → q, ~q / • ~p                  |
  | **Generalization**               | p / • p ∨ q ; q / • p ∨ q         |
  | **Specialization**               | p ∧ q / • p ; p ∧ q / • q         |
  | **Elimination**                  | p ∨ q, ~q / • p ; p ∨ q, ~p / • q |
  | **Transitivity**                 | p → q, q → r / • p → r            |
  | **Proof by Division into Cases** | p ∨ q, p → r, q → r / • r         |
  | **Conjunction**                  | p, q / • p ∧ q                    |
  | **Contradiction Rule**           | ~p → false / • p                  |
- **Fallacies (Invalid Argument Forms):**
  - **Converse Error (Affirming the Consequent):** p → q, q / • p (invalid)
  - **Inverse Error (Denying the Antecedent):** p → q, ~p / • ~q (invalid)
- **Sound Argument:** Valid AND all premises are true.
- **Unsound Argument:** Not sound (invalid or has a false premise).
- **Contradiction Rule:** If assuming ~p leads to a contradiction, then p is true. (Heart of proof by contradiction.)

  Let me move next to a brief introduction to AI. Our course structure follows the core pattern of how intelligent agents operate. Humans are intelligent agents: we perceive our environment through sensory organs like our eyes, ears, and nose. Then, based on our goals, we plan a solution and execute it through actions like moving, talking, or eating. We are trying to replicate this exact loop for artificial intelligent agents. An AI agent interacts with an environment by perceiving it through sensors (like cameras for vision or microphones for audio) and then performing actions (like planning, classification, or forecasting). Consider a lower-primary math word problem: "John has 4 bags, and each bag has 6 marbles. How many marbles does he have in total?". If I give you this problem, what is the very first step to solve it? (Student suggests checking the conditions, like how many bags). I think you already jumped a few steps ahead. Checking conditions isn't the first thing we do. (Another student says they would try to understand the sentence). Again, you are analyzing the question, which still isn't step one. Because it is so natural to us, we don't even think of it as a separate task: the absolute first step is to simply *read* the question. You must perceive the text. If it's a text prompt, the system needs Natural Language Processing (NLP) to read it. If I hand you a physical piece of paper with the problem, the system needs to take a scan and use computer vision to perceive the image before it can even attempt to extract details. This is perception intelligence, and without it, nothing else happens. Artificial perception capabilities finally beat human benchmarks around the early 2010s, which was the first major breakthrough that made AI wildly popular. After perception (reading), you move to understanding and identifying the question. This requires abstracting out the key details and discarding the noise—this is called "Abstraction Intelligence". In our problem, abstraction means recognizing the numbers 4 and 6 and discarding irrelevant words. The next step is planning a solution, meaning deciding to add 6 four times, or simply multiplying 4 by 6. The actual calculation (getting 24) is the inferencing or reasoning stage. Finally, merely giving the answer isn't enough; you must communicate and explain your answer. If an AI gives an answer without an explanation, we don't trust it. For a complete AI system, we need perception, abstraction, reasoning, and explanation capabilities. Large Language Models have essentially encapsulated all of these steps; they can parse the environment, reason through it, and explain why a solution is presented in a specific way.

- [14:28:40 - 14:43:58] **Design Space, Expert Systems, and AI Winters**

  When designing an AI system, you must classify the problem environment across several dimensions in the design space. Are you working in a static or dynamic environment?. What is your representation scheme—are you using states, features, or relations?. Is the environment fully observable, where you have complete access to the domain, or partially observable?. Are the parameter types discrete or continuous?. Is the uncertainty deterministic or stochastic?. Finally, is the knowledge already given to you, or does the system need to learn it from scratch?. These dimensions dictate your design choices. For this course, we mostly assume our environments are fully observable; we do not cover partially observable systems here, as those belong in advanced AI modules. We will, however, deal with both deterministic and stochastic environments, and scenarios where knowledge is both known and unknown. Looking at the historical evolution, the first generation of modern AI systems in the 1950s was logic-based. For example, the "Logic Theorist," written in 1956 by Allen Newell, Herbert Simon, and Cliff Shaw, was the first program engineered for automated reasoning. In these logic-based expert systems, you needed a subject matter expert to provide domain knowledge, and a knowledge engineer to encode that knowledge into formal rules (like propositional logic) stored in a Knowledge Base. An Inference Engine would then access this base to reason and explain its answers. A famous example is the MYCIN expert system. However, the history of AI is marked by periods known as "AI Winters" where funding dried up. The first AI winter hit in the late 1960s. Governments had poured money into logic systems hoping they could translate Russian to English flawlessly. It turned out that while logic systems were great at proving theorems, they failed miserably at complex, ambiguous real-world tasks like language translation. The research receded into academia—hence "winter," a time of limited outdoor activity. In the 1970s, expert systems exploded in popularity again, but they hit a wall, leading to the second AI winter in the 1980s. The issues were twofold: scalability and uncertainty. You cannot easily write rules for a system with millions of variables, and traditional logic fails when knowledge is uncertain (e.g., a 70% chance of flu vs a 20% chance of COVID). To solve the uncertainty problem, researchers introduced Probabilistic Graphical Models. Judea Pearl, a mathematician and physicist at UCLA, realized that expert knowledge could be represented structurally using graphs and conditional probabilities, creating Bayesian Networks. He later won the Turing Award for this. This allowed for probabilistic inference. Yet, building massive graphs manually still required an expert. The ultimate goal became causal AI—identifying cause and effect directly from data without a human expert dictating the rules.  

  在设计AI系统时，必须在设计空间的几个维度上对问题环境进行分类。你是在静态还是动态环境中工作？你的表示方案是什么——是使用状态、特征还是关系？环境是完全可观察的（你拥有对领域的完整访问权限），还是部分可观察的？参数类型是离散的还是连续的？不确定性是确定性的还是随机的？最后，知识是已经给定的，还是系统需要从头开始学习？这些维度决定了你的设计选择。在本课程中，我们主要假设环境是完全可观察的；我们这里不涵盖部分可观察系统，因为那些属于高级AI模块的内容。不过，我们将处理确定性和随机性环境，以及知识已知和未知的情况。回顾历史演变，1950年代第一代现代AI系统是基于逻辑的。例如，1956年由Allen Newell、Herbert Simon和Cliff Shaw编写的“逻辑理论家（Logic Theorist）”是第一个为自动推理设计的程序。在这些基于逻辑的专家系统中，你需要一个领域专家来提供领域知识，并需要一个知识工程师将这些知识编码为正式规则（如命题逻辑），存储在知识库中。然后，推理引擎会访问这个知识库进行推理并解释其答案。一个著名的例子是MYCIN专家系统。然而，AI的历史上有一段被称为“AI寒冬”的时期，当时资金枯竭。第一个AI寒冬在1960年代末袭来。各国政府曾将大量资金投入逻辑系统，希望它们能完美地将俄语翻译成英语。结果证明，虽然逻辑系统在证明定理方面非常出色，但在语言翻译等复杂、模棱两可的现实世界任务中却一败涂地。研究退回到了学术界——因此被称为“寒冬”，一个户外活动有限的时期。在1970年代，专家系统再次受到热捧，但随后碰壁，导致了1980年代的第二次AI寒冬。问题有两方面：可扩展性和不确定性。你很难为一个拥有数百万个变量的系统编写规则，而且当知识不确定时（例如，70%的可能性是流感，20%的可能性是COVID），传统逻辑就会失效。为了解决不确定性问题，研究人员引入了概率图模型。UCLA的数学家和物理学家Judea Pearl意识到，专家知识可以使用图和条件概率在结构上表示出来，从而创建了贝叶斯网络。他后来因此获得了图灵奖。这使得概率推理成为可能。然而，手动构建庞大的图仍然需要专家。最终的目标变成了因果AI——直接从数据中识别因果关系，而不需要人类专家来口述规则。

- [14:43:58 - 14:53:21] **Machine Learning, Deep Learning, and Transformers**

  If we don't have human experts to define the rules, we must rely on Machine Learning, which became popular from the 1990s onward. A machine learning pipeline involves data pre-processing, modeling, and inferencing. This era was fueled by the rise of the internet providing abundant data, powerful processors, and matured algorithms. Traditional ML ruled until the 2010s. Then, a perfect alignment of stars occurred. Nvidia had been designing GPUs for gaming, highly optimized for matrix manipulations that could be parallelized. Researchers realized that Deep Learning also requires massive matrix multiplications. By utilizing GPUs, having access to massive datasets, and refining hardware, Deep Learning broke through. In 2012-2013, deep learning architectures decisively won the ImageNet Large Scale Visual Recognition Challenge (ILSVRC), heavily outperforming traditional techniques in error rates as dataset sizes grew. The key advantage of deep neural networks is that they automate the data pre-processing step known as feature engineering. You no longer needed specialized domain knowledge (like specialized audio or image processing algorithms) to extract meaningful features; the deep learning model learns to extract them automatically. We saw breakthroughs in computer vision and reinforcement learning (like DeepMind's AlphaStar in Starcraft II). The next monumental breakthrough came in 2017 with the introduction of the Transformer architecture. Previous deep learning models processed sequential data serially, which was a massive bottleneck. The beauty of the Transformer is that it parallelizes the training process across massive datasets. This parallel processing capability, combined with massive RAM increases, birthed the Large Language Models (LLMs) like GPT in the early 2020s. Taxonomically, AI is broadly split into Symbolic AI and Sub-symbolic AI. Symbolic AI includes knowledge-based expert systems and statistical learning methods like Decision Trees, where variables are interpretable and carry real-world meaning. Sub-symbolic AI includes methods like Support Vector Machines and Neural Networks. Sub-symbolic models are effectively "black boxes"; a variable $x=10$ inside a deep network has no easily interpretable real-world meaning to us. - [15:06:01 - 15:15:56] **Syllogisms and Rules of Inference**

  Let's look at a classic deductive syllogism: "Premise 1: All men are mortal. Premise 2: Socrates is a man. Conclusion: Socrates is mortal". The Greek philosophers are like gangsters; they don't ask for mathematical proofs for these base premises, you just take them as axioms that are considered true. From these, we have several formalized Rules of Inference. The first is **Modus Ponens**. It states: If Statement 1 is True, then Statement 2 is True (Premise 1). We know Statement 1 is True (Premise 2). Therefore, Statement 2 is True (Conclusion). For example, if Premise 1 is "If it rains, it is cloudy," and Premise 2 is "It rains," we conclude "It is cloudy". The second is **Modus Tollens**. It states: If Statement 1 implies Statement 2, and we know Statement 2 is *not* true, we conclude Statement 1 is *not* true. Using the same example, if it is *not* cloudy, we can confidently conclude it is *not* raining. These inference rules are Tautologies—statements that are inherently always true. Another rule is **Elimination**: If we know Statement 1 OR Statement 2 is true, and we are told Statement 2 is false, then Statement 1 must be true. Finally, **Transitivity**: If Statement 1 implies Statement 2, and Statement 2 implies Statement 3, then Statement 1 implies Statement 3. If you recall high school math, this is the underlying principle for proof by induction.  

  让我们来看一个经典的演绎三段论：“前提1：所有人都是终有一死的。前提2：苏格拉底是人。结论：苏格拉底是终有一死的。”古希腊哲学家就像黑帮一样；他们不要求为这些基本前提提供数学证明，你只需把它们当作被认为是真的公理来接受。由此，我们有几个形式化的推理规则。第一个是**肯定前件式（Modus Ponens）**。它指出：如果陈述1为真，那么陈述2为真（前提1）。我们知道陈述1为真（前提2）。因此，陈述2为真（结论）。例如，如果前提1是“如果下雨，天就是多云的”，前提2是“下雨了”，我们得出结论“天是多云的”。第二个是**否定后件式（Modus Tollens）**。它指出：如果陈述1蕴含陈述2，并且我们知道陈述2*不*为真，我们得出结论陈述1*不*为真。使用同样的例子，如果天*不*多云，我们可以自信地得出结论，现在*没*下雨。这些推理规则是永真式（Tautologies）——本质上总是为真的陈述。另一个规则是**析取三段论（Elimination）**：如果我们知道陈述1或陈述2为真，并且被告知陈述2为假，那么陈述1必定为真。最后是**传递性（Transitivity）**：如果陈述1蕴含陈述2，且陈述2蕴含陈述3，那么陈述1蕴含陈述3。如果你回想一下高中的数学，这就是数学归纳法证明的潜在原理。

- [15:15:56 - 15:26:44]**Truth Tables and Implication Logic**

  Let us delve into building truth tables, specifically focusing on the hardest one: the implication statement `P ⇒ Q`. Understanding this is the most critical hurdle to understanding logic-based systems. By definition, if `P` is true, then `Q` is true. But if `P` is false, the statement makes *no claim* on `Q`. In conditional logic, the condition (`P`) is the antecedent, and the conclusion (`Q`) is the consequent. Let's look at mathematical examples to determine if the *statement as a whole* is true or false. Consider: `If 1+1=2, then 2+3=5.` The antecedent is true, and the consequent is true. The statement as a whole is true. Consider: `If 1+1=2, then 2+3=4.` The antecedent is true, but the consequent is false. Thus, the statement as a whole is definitively false. You cannot have rules like this in your knowledge base. Now consider this contradictory, counterintuitive example: `If 1=0, then 1+2=4.` Is this statement true or false? Your condition (`1=0`) is false. According to logic rules, because the antecedent is false, you don't even look at the conclusion. You simply make no claim, and the statement as a whole evaluates to *True*. In logic, we call these "vacuously true" statements. It seems useless to say "If 1=0, then 1+2=4 is true," and practically, it is an invariant, redundant rule. But why is the truth table designed this way? Because in a reasoning algorithm evaluating thousands of rules, if the condition isn't met, the algorithm must bypass it without breaking the chain of logic, treating the unused path as vacuously true so it doesn't corrupt the knowledge base.  

  让我们深入研究一下构建真值表，特别是集中在最难的一个：蕴含陈述 `P ⇒ Q`。理解这一点是理解基于逻辑的系统的最关键障碍。根据定义，如果 `P` 为真，那么 `Q` 为真。但如果 `P` 为假，该陈述对 `Q` *不做任何断言*。在条件逻辑中，条件（`P`）是前件，结论（`Q`）是后件。让我们通过数学例子来确定*整个陈述*是真还是假。

  考虑：`如果 1+1=2，那么 2+3=5。`前件为真，后件也为真。整个陈述为真。

  考虑：`如果 1+1=2，那么 2+3=4。`前件为真，但后件为假。因此，整个陈述肯定是假的。你的知识库中不能有这样的规则。

  现在考虑这个矛盾且有悖直觉的例子：`如果 1=0，那么 1+2=4。`这个陈述是真还是假？你的条件（`1=0`）是假的。根据逻辑规则，因为前件是假的，你甚至不用看结论。你只是不做任何断言，整个陈述的结果被评估为*真*。在逻辑中，我们称之为“空真（vacuously true）”陈述。说“如果1=0，那么1+2=4为真”似乎毫无用处，在实践中，它也是一条不变的、冗余的规则。但是为什么真值表要这样设计呢？因为在评估数千条规则的推理算法中，如果条件不满足，算法必须绕过它而不破坏逻辑链，将未使用的路径视为空真，这样就不会破坏知识库。

- [15:43:26 - 15:54:38] **Valid Arguments, Converse, and Inverse Errors**

  Let's look at how we check if a sentence or deduction is true. This is useful for checking whether your knowledge base is correct or if you are making correct deductions. If you have a wrong knowledge base, your conclusions will inherently be wrong. Assume your knowledge base is correct and contains the rule: "If it rains, then it is cloudy," along with the fact: "It rains." But we never explicitly stated the inverse rule in our premises. Knowing P ⇒ Q is true does not mean ¬P ⇒ ¬Q is true. You implicitly assumed the inverse was true to reach that conclusion, making the reasoning invalid. - [15:54:38 - 16:08:25] **Practical Reasoning Example and Tool Demo**

  A real-world knowledge-based system operates on these exact principles. You have a set of sentences (your knowledge) and you query it to get a true or false answer. More advanced systems like first-order or fuzzy logic are all built on these foundational building blocks like Modus Ponens and Modus Tollens. Let's try a practical reasoning example.   A. If I was reading the newspaper in the kitchen, then my glasses are on the kitchen table.

  B. If my glasses are on the kitchen table, then I saw them at breakfast.

  C. I did not see my glasses at breakfast.

  D. I was reading the newspaper in the living room or I was reading the newspaper in the kitchen.

  E. If I was reading the newspaper in the living room then my glasses are on the coffee table.

  Can you deduce whether your glasses are on the coffee table? Yes. We start with facts C and B. Because we did not see the glasses at breakfast (C is false), we use Modus Tollens on B to deduce that the glasses are not on the kitchen table. Next, we use Modus Tollens on A: since the glasses are not on the kitchen table, we deduce we were not reading the newspaper in the kitchen. Then, we look at D (a disjunction). Since we know we were not in the kitchen, by Elimination, we deduce we were reading in the living room. Finally, applying Modus Ponens to E, since we were reading in the living room, we logically conclude the glasses are on the coffee table. This is how human logic works, but converting this into an algorithm for machines is challenging.

Natural language is diverse; "if-then" statements can be written in many different ways. The tool captures those patterns and assigns abstract symbols (like P and Q) to the text phrases. For instance, it takes the phrase "I was reading the newspaper in the kitchen" and assigns it a symbol. Then it builds the Knowledge Base statement by statement. Once the KB is built, you can input the query: "My glasses are on the coffee table." The inference engine evaluates it and not only outputs "True," but also provides a reasoning tree explaining exactly why it is true, tracing the logic steps. This highlights our key objective for week one and two: understanding how to translate natural language into different propositional forms, and learning the algorithmic reasoning strategies (like Model Checking, Proof by Contradiction, and Resolution) to process them.

  A. 如果我在厨房看报纸，那么我的眼镜就在厨房的桌子上。

  B. 如果我的眼镜在厨房的桌子上，那么我在吃早餐时就看到它们了。

  C. 我吃早餐时没有看到我的眼镜。

  D. 我在客厅看报纸，或者我在厨房看报纸。

  E. 如果我在客厅看报纸，那么我的眼镜就在茶几上。

  你能推断出你的眼镜是否在茶几上吗？是的。我们从事实C和B开始。因为我们在吃早餐时没有看到眼镜（C为假），我们对B使用否定后件式（Modus Tollens），推断出眼镜不在厨房的桌子上。接下来，我们对A使用否定后件式：既然眼镜不在厨房的桌子上，我们推断我们没有在厨房看报纸。然后，我们看D（一个析取式）。既然我们知道我们不在厨房，通过析取三段论（Elimination），我们推断我们确实在客厅看报纸。最后，对E应用肯定前件式（Modus Ponens），既然我们在客厅看报纸，我们逻辑上得出结论：眼镜在茶几上。这就是人类逻辑运作的方式，但将其转化为机器算法是一项挑战。

  让我给你们展示一个小演示，这是以前一位毕业设计学生开发的一个能使这一过程自动化的工具。该应用程序接收自然语言句子并将其转换为命题逻辑。自然语言是多种多样的；“if-then”语句可以用许多不同的方式编写。该工具捕捉这些模式，并为文本短语分配抽象符号（如P和Q）。例如，它提取短语“我在厨房看报纸”并为其分配一个符号。然后它逐句构建知识库。知识库构建完成后，你可以输入查询：“我的眼镜在茶几上。”推理引擎对其进行评估，不仅输出“真（True）”，而且还提供一棵推理树，确切地解释为什么它是真的，追溯逻辑步骤。这突出了我们第一周和第二周的核心目标：理解如何将自然语言转化为不同的命题形式，并学习算法推理策略（如模型检验、反证法和归结）来处理它们。

- [16:08:25 - 16:18:32] **Knowledge Bases and Valid Propositional Syntax**

  In a typical AI architecture, you have a Knowledge Base and an Inference Engine. The Knowledge Base contains domain-specific rules and facts obtained from human experts, encoded as formal logical sentences. The Inference Engine is the actual reasoning mechanism; it is domain-independent, meaning the algorithm remains the same whether it's applied to medicine or robotics. The fundamental syntax of a rule is "IF [antecedent] THEN [consequent]". The antecedent goes by many names—condition, premise, independent variable—while the consequent is also called the conclusion, action, result, or dependent variable. A knowledge base can have hundreds, thousands, or even millions of these rules. While a human can manually trace maybe ten rules, we need efficient, scalable algorithms to handle a million rules without exhaustive manual labor. To do this, we must precisely define the syntax of our propositional language. We use symbols (e.g., Room_A_Clean, Room_B_Clean) which represent binary variables that take only 'true' or 'false' values. An atomic sentence is just the simple symbol itself without any connectives. A complex sentence is formed by combining symbols using logical connectives like negation, conjunction, disjunction, implication, and biconditional. What makes a sentence well-formed in propositional logic? A single symbol like P is valid. ¬P is valid. ¬(¬P) is also a valid complex sentence. P ∧ Q and P ∨ Q are valid. However, simply writing P ¬Q is invalid syntax; negation is a unary operator, not a connective to join two variables. Similarly, P + Q is invalid because addition is not a logical connective. The machine needs these sentences written in perfectly valid syntax to process them.

  在一个典型的AI架构中，你有一个知识库和一个推理引擎。知识库包含从人类专家那里获得的特定领域的规则和事实，被编码为正式的逻辑语句。推理引擎是实际的推理机制；它是与领域无关的，这意味着无论应用于医学还是机器人技术，算法都保持不变。一条规则的基本语法是“如果 [前件] 那么 [后件]”。前件有许多名称——条件、前提、自变量——而后件也被称为结论、动作、结果或因变量。一个知识库可能有数百、数千甚至数百万条这样的规则。虽然人类也许可以手动追踪十条规则，但我们需要高效、可扩展的算法来处理一百万条规则，而不需要耗尽人力。为此，我们必须精确定义我们命题语言的语法。我们使用符号（例如，Room_A_Clean，Room_B_Clean）来表示仅取“真（true）”或“假（false）”值的二元变量。原子句子只是简单的符号本身，不带任何连接词。复杂句子是通过使用逻辑连接词（如否定、合取、析取、蕴含和双条件）组合符号而形成的。在命题逻辑中，什么构成了一个格式良好的句子？像 P 这样的单一符号是有效的。¬P 是有效的。¬(¬P) 也是一个有效的复杂句子。P ∧ Q 和 P ∨ Q 都是有效的。然而，简单地写 P ¬Q 是无效的语法；否定是一个一元运算符，而不是连接两个变量的连接词。同样，P + Q 是无效的，因为加法不是逻辑连接词。机器需要这些句子以完全有效的语法编写才能处理它们。

- [16:18:32 - 16:31:25] **Semantics, Models, Tautologies, and Satisfiability**

  Once we understand syntax, we move to semantics, which gives meaning to the sentences. We have already covered truth tables, but now we introduce the concept of "Models" (also referred to as "Possible Worlds"). A model is simply an assignment of truth values to the variables in a sentence. For a sentence with n variables, there are 2^n possible models (or assignments). For example, if we have just variable P, there are two models: {P=true} and {P=false}. For two variables, P and Q, there are four possible models. When we evaluate a sentence, we look at the set of models for which the sentence is mathematically true. For the sentence P, out of the four possible models involving P and Q, it is true in two of them: {P=true, Q=true} and {P=true, Q=false}. For the implication P ⇒ Q, out of the four models, the sentence evaluates to true in three of them. Now, let's define some critical terminology. A sentence is a Tautology (or is Valid) if it is true in all possible models. For example, P ∨ ¬P is a tautology; whether P is true or false, the statement as a whole is always true. Conversely, a Contradiction is a sentence that is false in all models. P ∧ ¬P is a contradiction; it can never be true. Finally, Satisfiability: a sentence is satisfiable if it is true in at least one model. P ∧ Q is satisfiable because it is true when both P and Q are true. Determining satisfiability (the SAT problem) is a highly active domain in computer science research, especially for fault diagnosis.

  一旦我们理解了语法，我们就会进入语义，它赋予句子以意义。我们已经讲过真值表，但现在我们要引入“模型”（也称为“可能世界”）的概念。模型仅仅是对句子中变量的真值赋值。对于一个有 n 个变量的句子，有 2^n 个可能的模型（或赋值）。例如，如果我们只有变量 P，有两个模型：{P=true} 和 {P=false}。对于两个变量 P 和 Q，有四个可能的模型。当我们评估一个句子时，我们看的是使该句子在数学上为真的模型集合。对于句子 P，在涉及 P 和 Q 的四个可能模型中，它在其中两个模型中为真：{P=true, Q=true} 和 {P=true, Q=false}。对于蕴含式 P ⇒ Q，在四个模型中，该句子在其中三个模型中被评估为真。现在，让我们定义一些关键术语。如果一个句子在所有可能的模型中都为真，那么它就是一个永真式（Tautology）（或者是有效的（Valid））。例如，P ∨ ¬P 是一个永真式；无论 P 是真还是假，整个陈述总是为真。相反，矛盾式（Contradiction）是一个在所有模型中都为假的句子。P ∧ ¬P 是一个矛盾式；它永远不可能为真。最后是可满足性（Satisfiability）：如果一个句子在至少一个模型中为真，它就是可满足的。P ∧ Q 是可满足的，因为当 P 和 Q 都为真时它为真。确定可满足性（SAT问题）是计算机科学研究中非常活跃的领域，特别是在故障诊断方面。

- [16:31:25 - 16:37:58] **Logical Equivalence**

  We say two sentences, α and β, are Logically Equivalent (α ≡ β) if they share the exact same models—meaning they evaluate to the same truth values across all possible assignments. Alternatively, we can prove equivalence if the biconditional statement α ⇔ β is a tautology (always evaluates to true). We use standard logical equivalences to translate propositional sentences from one form to another to simplify algorithms. You do not need to memorize these for the exam; a table will be provided. Some are trivial, like commutativity (A ∧ B ≡ B ∧ A) and double-negation elimination (¬(¬α) ≡ α). Others, like De Morgan's Laws, are crucial. However, the most important equivalence for our purposes is Implication Elimination: The statement α ⇒ β is logically equivalent to ¬α ∨ β. Let's prove it with a truth table. If we have α and β, we can derive ¬α. The implication α ⇒ β is only false when α is true and β is false; otherwise, it is true. Now evaluate the disjunction ¬α ∨ β. It evaluates to exactly the same column of truth values. Because the truth tables match perfectly, α ⇒ β ≡ ¬α ∨ β. We use this rule frequently because it removes the implication connective, transforming the sentence into a disjunction, which is a required step for converting knowledge bases into Conjunctive Normal Form (CNF) for automated theorem proving.

  如果两个句子 α 和 β 拥有完全相同的模型——意味着它们在所有可能的赋值下评估出相同的真值，我们就说它们是逻辑等价的（α ≡ β）。或者，如果双条件语句 α ⇔ β 是永真式（评估结果总是为真），我们也可以证明它们的等价性。我们使用标准逻辑等值式将命题句子从一种形式转换为另一种形式，以简化算法。你们不需要为了考试死记硬背这些；我们会提供一个表格。有些等值式很基本，比如交换律（A ∧ B ≡ B ∧ A）和双重否定消除（¬(¬α) ≡ α）。其他的一些，比如德摩根定律（De Morgan's Laws），则非常关键。然而，对我们来说最重要的等值式是蕴含消除（Implication Elimination）：陈述 α ⇒ β 逻辑等价于 ¬α ∨ β。让我们用真值表来证明它。如果我们有 α 和 β，我们可以推导出 ¬α。蕴含式 α ⇒ β 只有当 α 为真且 β 为假时才为假；否则，它为真。现在评估析取式 ¬α ∨ β。它评估出的真值列完全相同。因为真值表完美匹配，所以 α ⇒ β ≡ ¬α ∨ β。我们频繁地使用这条规则，因为它消除了蕴含连接词，将句子转化为析取式，这是将知识库转换为合取范式（CNF）以进行自动定理证明的必经步骤。

- [16:37:58 - 16:50:23] **Conjunctive Normal Form (CNF)**

  Some reasoning algorithms require the entire knowledge base to be in a specific structure called Conjunctive Normal Form (CNF). Let's define the grammar of CNF from the bottom up. The base elements are Symbols (e.g., P, Q). A Literal is either a symbol or the negation of a symbol (e.g., P, ¬P, Q). A Clause is a disjunction (OR) of literals (e.g., P ∨ ¬Q). Note that a single literal also qualifies as a valid clause. Finally, a CNF sentence is a conjunction (AND) of clauses. Therefore, CNF looks like a series of OR statements bracketed together by AND statements: (Clause_1) ∧ (Clause_2) ∧ ... ∧ (Clause_m).

  Real-world knowledge is almost never naturally written in CNF; you must convert it. Let's walk through translating a complex sentence, the biconditional B_1,1 ⇔ (P_1,2 ∨ P_2,1), into CNF.

  Step 1: Biconditional Elimination. We replace α ⇔ β with (α ⇒ β) ∧ (β ⇒ α). This gives us (B_1,1 ⇒ (P_1,2 ∨ P_2,1)) ∧ ((P_1,2 ∨ P_2,1) ⇒ B_1,1).

  Step 2: Implication Elimination. Apply the rule α ⇒ β ≡ ¬α ∨ β to both halves. This yields (¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ (¬(P_1,2 ∨ P_2,1) ∨ B_1,1).

  Step 3: Move Negations Inward. In CNF, negations must only appear directly attached to symbols. We use De Morgan's Law (¬(A ∨ B) ≡ ¬A ∧ ¬B) on the second half. This gives us (¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ ((¬P_1,2 ∧ ¬P_2,1) ∨ B_1,1). The first half is already a valid clause, but the second half has an AND nested inside an OR, which violates CNF structure.

  Step 4: Distributivity. We distribute the OR over the AND using the rule α ∨ (β ∧ γ) ≡ (α ∨ β) ∧ (α ∨ γ). Applying this to the second half yields (¬P_1,2 ∨ B_1,1) ∧ (¬P_2,1 ∨ B_1,1).

  The final CNF sentence is the conjunction of three distinct clauses: (¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ (¬P_1,2 ∨ B_1,1) ∧ (¬P_2,1 ∨ B_1,1). We have successfully translated a single biconditional sentence into a mathematically rigorous CNF format required by automated theorem provers.

  一些推理算法要求整个知识库处于一种特定的结构中，称为合取范式（CNF）。让我们自下而上地定义CNF的语法。基本元素是符号（Symbols）（例如，P, Q）。文字（Literal）要么是符号，要么是符号的否定（例如，P, ¬P, Q）。子句（Clause）是文字的析取（OR）（例如，P ∨ ¬Q）。请注意，单个文字也有资格成为有效的子句。最后，CNF句子是子句的合取（AND）。因此，CNF看起来像是一系列通过AND语句连接在一起的OR语句：(Clause_1) ∧ (Clause_2) ∧ ... ∧ (Clause_m)。

  现实世界的知识几乎从未自然地以CNF编写；你必须对其进行转换。让我们演示如何将一个复杂的句子，即双条件语句 B_1,1 ⇔ (P_1,2 ∨ P_2,1) 转换为CNF。

  步骤1：双条件消除。我们将 α ⇔ β 替换为 (α ⇒ β) ∧ (β ⇒ α)。这给了我们 (B_1,1 ⇒ (P_1,2 ∨ P_2,1)) ∧ ((P_1,2 ∨ P_2,1) ⇒ B_1,1)。

  步骤2：蕴含消除。对两半应用规则 α ⇒ β ≡ ¬α ∨ β。这产生了 (¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ (¬(P_1,2 ∨ P_2,1) ∨ B_1,1)。

  步骤3：将否定向内移。在CNF中，否定必须只直接附加在符号上。我们在后半部分使用德摩根定律（¬(A ∨ B) ≡ ¬A ∧ ¬B）。这给了我们 (¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ ((¬P_1,2 ∧ ¬P_2,1) ∨ B_1,1)。前半部分已经是一个有效的子句，但后半部分在一个OR里面嵌套了一个AND，这违反了CNF的结构。

  步骤4：分配律。我们使用规则 α ∨ (β ∧ γ) ≡ (α ∨ β) ∧ (α ∨ γ) 将OR分配到AND上。将其应用于后半部分产生 (¬P_1,2 ∨ B_1,1) ∧ (¬P_2,1 ∨ B_1,1)。

  最终的CNF句子是三个不同子句的合取：(¬B_1,1 ∨ P_1,2 ∨ P_2,1) ∧ (¬P_1,2 ∨ B_1,1) ∧ (¬P_2,1 ∨ B_1,1)。我们已成功地将单个双条件语句转换为自动定理证明器所需的数学上严谨的CNF格式。

- [16:50:23 - 16:52:16] **Definite Clauses and Horn Clauses**

  There are other restricted propositional forms you must know, specifically Definite Clauses and Horn Clauses. A Definite Clause is a specific type of CNF clause that contains exactly one positive literal. For example, the clause ¬X ∨ Y is a definite clause because it has one positive literal (Y) and one negative literal (¬X). A single symbol X is also a definite clause. However, X ∨ Y is not a definite clause because it has two positive literals. Similarly, ¬X ∨ ¬Y is not a definite clause because it has zero positive literals. A Horn Clause is slightly broader; it allows at most one positive literal. This means a Horn clause can have one positive literal (like a definite clause) or zero positive literals (like ¬X ∨ ¬Y). Therefore, all definite clauses are Horn clauses, but not all Horn clauses are definite clauses. Why do we care? Because if we restrict our knowledge base to only use Horn clauses, we can use highly efficient inferencing algorithms (like Forward Chaining and Backward Chaining) that rely solely on Modus Ponens, dramatically speeding up the reasoning process. We will explore these algorithms in detail next week.

  你们还必须了解其他受限的命题形式，特别是确定子句（Definite Clauses）和霍恩子句（Horn Clauses）。确定子句是一种特定类型的CNF子句，它包含恰好一个正文字。例如，子句 ¬X ∨ Y 是一个确定子句，因为它有一个正文字（Y）和一个负文字（¬X）。单个符号 X 也是一个确定子句。然而，X ∨ Y 不是一个确定子句，因为它有两个正文字。同样，¬X ∨ ¬Y 不是一个确定子句，因为它有零个正文字。霍恩子句的范围稍广一些；它允许最多一个正文字。这意味着霍恩子句可以有一个正文字（像确定子句一样）或零个正文字（像 ¬X ∨ ¬Y）。因此，所有确定子句都是霍恩子句，但并非所有霍恩子句都是确定子句。我们为什么要在意这个？因为如果我们将知识库限制为仅使用霍恩子句，我们就可以使用完全依赖于肯定前件式（Modus Ponens）的高效推理算法（如前向链接和后向链接），从而极大地加快推理过程。下周我们将详细探讨这些算法。
