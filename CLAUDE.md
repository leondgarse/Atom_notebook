## Layout

- `public/<year>/MM-DD_<topic>.md` — the notes. Older topics: `public/2013_*`,
  `public/2016_QT_c++`. Filenames mix English and Chinese; keep them as is.
- Notes are large topic dumps (median ~24 KB, some >1 MB). Read with offsets or
  grep for headings; don't load whole huge files.
- Many notes start with an Atom-era `<!-- TOC ... -->` block. Keep it.
- `index/` — topic indexes, generated by `python3 index/build_index.py`
  (topic → note mapping lives in its `TOPICS`). Don't hand-edit the `.md` files.
- Each note ends with a generated `# Related` section between `<!-- related -->`
  markers, written by `python3 index/build_related.py --write` (TF-IDF over
  title/summary/tags/headings + shared tags/topics). Don't hand-edit it; re-run
  after adding notes or changing frontmatter, then re-run `build_index.py`.
  Hand-picked links for a note go in `RELATED` in `build_related.py`
  (they replace the computed ones; `[]` = no Related section).
- `public/README.md` — file tree of `public/`, generated by
  `cd public && python3 2017/folder_toc.py` (defaults: `-i ./ -o ./README.md`;
  skips images, hidden files and image-only folders). Re-run after adding,
  renaming or deleting notes; don't hand-edit.
- `README.md` — repo readme.
- macOS is case-insensitive (APFS): `readme.md` vs `README.md` once collided.
  Never create names differing only in case; rename via a temp name.

## Conventions

- Written in Pulsar/Atom style: content under a heading was indented 2 spaces.
  Converted (Oct 2026) to flush-left so Obsidian renders tables/code fences.
  New content: no indent under headings; blank line before tables;
  fenced code with a language tag.
- Note layout (from the former `.agent/rules/markdown_style.md`):
  - Document title: only the first H1 uses `# ___Title___`, followed directly
    by `***` on the next line, then one blank line.
  - Sections are `# Section` / `## Subsection`; no blank line between an H1
    and its immediate H2.
  - Between sections: `***` right after the section's last content line (no
    blank line before), one blank line after, then the next `# Section`.
  - List items may start with a bold lead-in, e.g. `- **Concept:**`. Code blocks
    belonging to a list item are indented to align with its text.
  - Code fences name the language (`py`, `sh`). For Python output use
    `print(f"{var = }")` and put the expected output in `#` comments below.
    Keep inline output comments in shell commands (e.g. `# 1.7G`).
- Obsidian syntax traps in plain text (outside code spans/fences): `$…$` / `$$`
  (math), `%%` (comment), `==…==` (highlight), `[[` (wikilink), unknown tags
  like `<remote>` (raw HTML); single `~…~` is strikethrough on GitHub. Escape
  them (`\$`, `\%\%`, `\<`, `\~`) or put them in backticks. Tables must be
  flush-left with a blank line before.
- Links: use **relative Markdown links** `[text](../2022/01-09_imagenet_train.md#heading)`
  so they work both on GitHub and in Obsidian. Avoid `[[wikilinks]]` in `public/`
  (GitHub doesn't render them).
  Heading anchors differ: GitHub wants the slug (`#token-label`), Obsidian the
  heading text (`#Token%20label`). One link works in both only when the heading
  has no spaces or punctuation; otherwise prefer the Obsidian form.
- Viewed in Obsidian through the hub vault `~/obsidian_projects`
  (symlinks to this repo and others). Smart Connections plugin is used locally.
